# 사이트 헬스체크

## 무엇을 하나
- 1시간마다 GitHub Actions가 사이트를 점검하고, **이상이 있을 때만** GitHub 이슈(라벨 `healthcheck`)를 열어 알립니다.
  이슈 본문이 `@mononono97`을 부르기 때문에 GitHub 알림 메일(그리고 GitHub 앱을 쓰면 휴대폰 알림)로 옵니다.
- 비밀값 `NTFY_TOPIC`을 넣으면 **휴대폰 푸시 알림 앱 ntfy**로도 바로 옵니다(이상 발생·내용 바뀜은 긴급 알림, 복구는 보통 알림).
  알림을 누르면 GitHub 이슈가 열립니다.
- 같은 이상이 계속되면 매시간 이슈 본문만 조용히 갱신하고(알림 없음), 이상 내용이 바뀌면 댓글로 한 번 알리고,
  모두 정상으로 돌아오면 "정상으로 돌아옴" 댓글을 달고 이슈를 닫습니다(닫힘도 알림으로 옴).
- 매 실행 결과는 Actions → "사이트 헬스체크" → 실행 하나를 열면 요약(Summary)에 표로 보입니다.

| 묶음 | 점검 | 이상으로 보는 경우 |
|---|---|---|
| 접속 | 첫 화면, `sw.js`, `admin.html`, 부스컷 이미지, Firebase SDK(gstatic) | 200이 아니거나 연결 실패(30초 뒤 다시 해도 같을 때만), 10초 넘게 걸림 |
| 배포 | 사이트의 `index.html` 코드 지문이 main의 `index.html`과 같은지 | main에서 바뀐 지 30분이 지났는데도 사이트가 예전 코드(Cloudflare 빌드 실패) |
| 로그인 | Firebase 승인 도메인에 사이트 주소가 있는지, Google 로그인 제공자가 켜져 있는지 | 둘 중 하나라도 아님(로그인 버튼이 동작하지 않음) |
| 동기화 | 점검 전용 계정으로 로그인해 Firestore에 쓰고 다시 읽기 | 로그인·쓰기·읽기 실패, 쓴 값과 읽은 값이 다름 |
| 동기화 | 로그인 안 한 요청이 `users` 문서를 못 읽는지(보안 규칙), 상품 정보 글 문서(`boothPosts/main`)를 읽을 수 있는지 | 남의 문서가 읽힘 / 상품 정보 글을 못 읽음 |
| 할당량 | Firestore 오늘 읽기·쓰기·삭제(Blaze 플랜일 때만), Cloudflare Workers 오늘 요청 | 무료 한도의 70% 이상. Spark 플랜은 사용량을 못 읽어서 다 쓴 순간(동기화 점검 429)에 알림 |
| (설정) | 비밀값·권한 | 키가 틀렸거나 권한이 없어 점검을 못 함(이것도 알림) |

비밀값을 아직 넣지 않은 점검은 "건너뜀"으로만 표시하고 알림은 보내지 않습니다.

## 왜 이렇게 했나
- **GitHub Actions + cron-job.org**: X 글 수집기와 같은 구조입니다. 이 저장소는 GitHub 자체 예약 실행이 몇 시간씩 빠져서
  ([부스 상품 정보](기능-부스-상품-정보.md) 참고), cron-job.org가 매시간 "Run workflow"를 대신 누르고 GitHub 예약(매시 41분)은 예비로 둡니다.
  별도 서버나 유료 서비스가 필요 없습니다.
- **알림을 GitHub 이슈로 한 이유** (비교한 방법)
  - GitHub 이슈: 추가 비밀값 없이 워크플로 기본 토큰으로 되고, 열림/닫힘이 곧 "지금 이상인지" 상태라서 같은 이상을 매시간 반복해
    알리지 않고 정상 복구도 알릴 수 있음. 기록이 남고 이슈 댓글로 메모도 가능. 알림은 GitHub 계정 메일·앱으로 옴. → **선택**
  - 메일 직접 보내기(Gmail SMTP): Gmail 2단계 인증과 앱 비밀번호를 비밀값으로 넣어야 하고, 반복 알림을 막으려면 상태를 따로 저장해야 함.
    버그 제보처럼 메일함으로 꼭 받고 싶으면 나중에 이슈 알림에 더해 붙일 수 있음.
  - 휴대폰 푸시(ntfy): GitHub 메일은 휴대폰에서 알림이 잘 안 울려서(사용자, 2026-11-03) 추가. 가입·토큰 없이 앱에서 주제 이름만 구독하면 되고,
    워크플로는 그 주제로 HTTPS 요청 한 번만 보냄. 주제 이름이 사실상 비밀번호라 GitHub 비밀값에 넣음. 텔레그램 봇(토큰·채팅 ID 필요),
    카카오톡 나에게 보내기(로그인 토큰을 두 달마다 갱신해야 함)보다 설정이 간단해서 선택.
  - Actions 실패 메일: 이상이 계속되면 매시간 메일이 오고, 점검 스크립트가 고장 난 것과 사이트 이상을 구별하기 어려움.
  - cron-job.org 자체 실패 알림: 응답 코드만 보므로 동기화·할당량은 못 봄.
- **동기화 점검을 실제 Google 로그인 대신 점검 전용 계정(uid `healthcheck-bot`)으로 한 이유**: Google 로그인 창은 사람이 눌러야 해서 자동화할 수 없습니다.
  대신 서비스 계정 키로 Firebase "맞춤 토큰"을 만들어 같은 Firebase Auth로 로그인하고, 사이트와 같은 Firestore 경로·보안 규칙·문서 모양
  (`users/{uid}.furstclass`)으로 쓰고 읽습니다. 관리자 권한으로 바로 쓰는 방식은 보안 규칙을 건너뛰어서 실제 사용자 상황과 달라 쓰지 않았습니다.
  Google 로그인 창 자체는 승인 도메인·제공자 설정 점검으로 대신합니다.
- **실사용 데이터를 건드리지 않음**: 점검은 `users/healthcheck-bot` 문서 하나에만 쓰고, 상품 정보 글 문서는 내용 없이 갱신 시각만 받습니다.
- **할당량을 거의 쓰지 않음**: 한 번에 쓰기 1, 읽기 약 3이라 하루 쓰기 24 / 읽기 약 72로 무료 한도(쓰기 2만 / 읽기 5만)의 0.2% 미만입니다.
- **배포 점검**: 2026-10-03처럼 Cloudflare 빌드가 실패하면 main은 바뀌었는데 사이트는 예전 그대로입니다. 버그 제보의 코드 지문
  (`tools/code_fingerprint.py`)을 그대로 써서 사이트와 main의 본문 스크립트를 비교합니다. 배포에 보통 1~2분 걸리므로 30분 여유를 둡니다.

## 어떻게 구현했나
- 워크플로: `.github/workflows/site-healthcheck.yml` (예약 매시 41분 + Run workflow, 입력 `push_test`로 휴대폰 시험 알림). main에서 실행할 때만 `--issue`로 이슈를 다루고,
  다른 브랜치에서 실행하면 결과만 보여 줍니다(이상이 있으면 실행이 빨간색).
- 스크립트: `tools/site_healthcheck.py`
  - 접속: `check_url()` 실패하면 30초 뒤 한 번 더. 첫 화면은 `const STORAGE_PREFIX =`가 들어 있는지도 확인.
  - 배포: `check_deploy()` 사이트 HTML과 `git show origin/main:index.html`의 `fingerprint()`를 비교, `git log -1 origin/main -- index.html` 시각으로 30분 여유.
  - 로그인: Identity Toolkit `GET /v1/projects`(승인 도메인), `accounts:createAuthUri`(google.com 제공자). 웹 API 키(공개값)만 씀.
  - 동기화: `check_sync()` 서비스 계정 키로 맞춤 토큰(uid `healthcheck-bot`) → `accounts:signInWithCustomToken` → ID 토큰으로
    Firestore REST `PATCH users/healthcheck-bot` (값: `furstclass.notes.HEALTHCHECK` = 무작위 문자열, `furstclass.updatedAt`) → `GET`으로 다시 읽어 비교.
    `check_public_firestore()` 로그인 없이 `users/healthcheck-bot` 읽기가 403인지, `boothPosts/main`이 읽히는지.
  - 할당량: `check_firestore_quota()` (Cloud Monitoring 은 결제 계정이 있어야 해서 Spark 플랜에서는 건너뜀) Cloud Monitoring `firestore.googleapis.com/document/{read,write,delete}_count`를 태평양 시간 자정(한국 17:00)부터 합산.
    `check_cloudflare_quota()` Cloudflare GraphQL `workersInvocationsAdaptive`로 UTC 자정(한국 09:00)부터 Worker 요청 합산. 이 사이트는 정적 파일만 제공해서
    보통 0건이고(정적 파일 요청은 무료·무제한), Worker 스크립트를 붙이게 되면 하루 10만 한도와 비교합니다.
  - 휴대폰 알림: `push_phone()` ntfy에 JSON으로 보냄(제목·이상 목록 최대 5줄·이슈 링크). 이슈를 열 때, 이상 내용이 바뀔 때, 복구될 때만 보내고
    같은 이상이 계속될 때는 보내지 않음. `NTFY_SERVER`로 다른 ntfy 서버도 쓸 수 있음(기본 https://ntfy.sh).
  - 기준: `HC_QUOTA_THRESHOLD`(기본 0.7). 알림 이슈: `sync_issue()` 이상 항목 이름 목록을 이슈 본문의 `<!-- hc-sig: ... -->`에 저장해 같은 이상인지 판단.
- 비밀값(GitHub → 저장소 Settings → Secrets and variables → Actions). 값은 위키에 적지 않습니다.
  - `FIREBASE_SA_KEY`: Firebase 프로젝트 `boothlist-4589c`의 서비스 계정 JSON 키 전체 (동기화·Firestore 할당량)
  - `CF_API_TOKEN`, `CF_ACCOUNT_ID`: Cloudflare 사용량 읽기 (Cloudflare 할당량)
  - `NTFY_TOPIC`: 휴대폰 푸시 알림(ntfy) 주제 이름
- 알아 둘 점: Firebase 콘솔 → Authentication → 사용자 목록에 `healthcheck-bot`(제공자: 맞춤) 사용자가 하나 생기고, 로그인 사용자 수가 1 늘어납니다.
  Firestore 사용량 숫자는 Cloud Monitoring 기준이라 몇 분 늦고 콘솔 숫자와 조금 다를 수 있습니다.

### 처음 한 번 설정 (사용자)
**1. Firebase 서비스 계정 키 → `FIREBASE_SA_KEY`** (동기화·Firestore 할당량 점검)
1. https://console.firebase.google.com/project/boothlist-4589c/settings/serviceaccounts/adminsdk 를 엽니다
   (Firebase 콘솔 → ⚙️ 프로젝트 설정 → 서비스 계정).
2. **새 비공개 키 생성** → 키 생성 → JSON 파일이 받아집니다. 이 키는 프로젝트 관리자 권한이라 채팅·저장소에 붙이지 마세요.
3. https://console.cloud.google.com/iam-admin/iam?project=boothlist-4589c 에서 `firebase-adminsdk-…@boothlist-4589c.iam.gserviceaccount.com`
   줄의 연필(수정) → **다른 역할 추가** → `Monitoring 뷰어`(Monitoring Viewer) → 저장. (Firestore 사용량을 읽는 권한)
4. https://console.cloud.google.com/apis/library/monitoring.googleapis.com?project=boothlist-4589c 에서 **Cloud Monitoring API**가
   "사용 설정됨"인지 확인하고, 아니면 사용 설정을 누릅니다.
5. GitHub 저장소 → Settings → Secrets and variables → Actions → **New repository secret**
   - Name: `FIREBASE_SA_KEY`, Secret: 받은 JSON 파일을 메모장으로 열어 내용 전체를 붙여 넣기 → Add secret.
   - 붙여 넣은 뒤 PC의 JSON 파일은 지워도 됩니다(다시 필요하면 새로 만들면 됨).

**2. Cloudflare API 토큰 → `CF_API_TOKEN`, `CF_ACCOUNT_ID`** (Cloudflare 할당량 점검, 선택)
1. https://dash.cloudflare.com/profile/api-tokens → **Create Token** → 맨 아래 **Custom token**의 Get started.
2. Token name: `헬스체크 사용량 읽기` / Permissions: `Account` · `Account Analytics` · `Read` /
   Account Resources: `Include` · 내 계정 / TTL: 끝 날짜 2026-12-31 → Continue to summary → Create Token → 값 복사.
3. 계정 ID: Cloudflare 대시보드 주소 `https://dash.cloudflare.com/<여기 32자리>/...` 또는 Workers & Pages 화면 오른쪽 "Account ID".
4. GitHub 비밀값 두 개 추가: `CF_API_TOKEN`(토큰), `CF_ACCOUNT_ID`(계정 ID).

**3. cron-job.org에 작업 C 추가** (매시간 실행)
- 수집기용 작업 A를 복제(Clone)하고 아래만 바꿉니다. 토큰은 같은 것을 씁니다.
  - Title: `퍼클 사이트 헬스체크`
  - URL: `https://api.github.com/repos/mononono97/FurryBoothList/actions/workflows/site-healthcheck.yml/dispatches`
  - Execution schedule: Every hour, 분은 **41**
  - Request body: `{"ref":"main"}`
- TEST RUN → **204**면 성공. Actions → "사이트 헬스체크"에 실행이 생깁니다.

**4. 휴대폰 푸시 알림(ntfy) → `NTFY_TOPIC`** (추천)
1. 휴대폰에 **ntfy** 앱 설치(안드로이드 Play 스토어 / 아이폰 App Store에서 "ntfy" 검색, 무료·가입 없음).
2. 주제 이름을 정합니다. 이름을 아는 사람은 누구나 알림을 보거나 보낼 수 있으니 짐작하기 어렵게 만드세요.
   예: `furryboothlist-` 뒤에 아무 영문·숫자 15자 이상 (`furryboothlist-k3v9q2m7x1z8p4w`). 이 이름은 채팅·저장소에 적지 마세요.
3. 앱에서 **+** (Subscribe to topic) → 주제 이름 입력 → Subscribe. (서버는 기본값 ntfy.sh 그대로)
4. GitHub 비밀값 `NTFY_TOPIC`에 같은 주제 이름을 넣습니다.
   시험: Actions → 사이트 헬스체크 → Run workflow에서 **"휴대폰 알림(ntfy) 시험 알림 보내기"**를 체크하고 실행 → 휴대폰에 "🔔 사이트 헬스체크 알림 시험"이 오면 끝.
5. 안드로이드는 앱 알림 설정에서 ntfy의 배터리 최적화를 끄면 알림이 늦지 않습니다. 아이폰은 앱을 처음 열 때 알림 허용.

**5. GitHub 알림 받는 곳 확인** (예비)
- https://github.com/settings/notifications 의 "Participating, @mentions and custom"에서 **Email**이 켜져 있는지 확인
  (GitHub 가입 메일로 옴). 휴대폰 알림을 원하면 GitHub 앱에 로그인하고 알림을 켭니다.

### 할당량 알림이 오면
- Firestore 읽기·쓰기 70%: 한국 17:00에 초기화됩니다. 그 전에 100%가 되면 그날 남은 시간 동안 로그인 동기화·상품 정보 글 불러오기가
  실패합니다(목록·메모는 기기 안 저장이라 계속 됨). 급하면 Firebase를 Blaze(종량제)로 올리면 한도가 없어지고, 이 정도 사용량이면 요금은 거의 0원입니다.
- Cloudflare Workers: 정적 파일만 제공하는 동안은 해당 없음.

## 확인 방법
1. GitHub → Actions → **사이트 헬스체크** → Run workflow(브랜치 main) → 1분쯤 뒤 실행을 열어 Summary의 점검 결과가 모두 ✅(또는 ⏭️ 건너뜀)인지 봅니다.
2. 비밀값을 넣은 뒤 다시 실행해 "동기화"·"할당량" 줄이 ✅로 바뀌는지 봅니다. ❌가 나오면 그 줄의 설명대로 설정을 고칩니다.
3. 알림 시험: 비밀값 `CF_ACCOUNT_ID`를 일부러 틀린 값으로 바꾸고 Run workflow → `healthcheck` 이슈가 열리고 휴대폰 ntfy 알림·메일이 오는지 확인 →
   값을 되돌리고 다시 실행 → 이슈에 "정상으로 돌아옴" 댓글이 달리고 닫히는지 확인.
4. 사이트 기능에는 손대지 않았으므로 우선순위 정렬·Google 로그인 동기화·메모·방문 상태·예산은 그대로입니다.
