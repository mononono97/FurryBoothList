# Google 로그인과 동기화

## 무엇을 하나
- 톱니바퀴 옆의 로그인 버튼으로 Google 로그인하면 메모·방문 상태·예산·우선순위·선입금·숨긴 상품 정보 글을 여러 기기에서 같이 쓸 수 있습니다.
- 로그인할 때(페이지를 열 때 포함) 클라우드 데이터와 병합합니다. 병합 결과가 클라우드와 같으면 다시 올리지 않습니다.
- 로그인 중 "데이터 초기화"는 클라우드 데이터도 지웁니다(경고 후). 자세한 내용은 [설정 메뉴와 초기화](기능-설정-메뉴와-초기화.md).
- 그 뒤로는 **편집을 마치면 자동으로 클라우드에 저장**됩니다(2026-11-03~). 마지막 편집 뒤 3초 동안 더 편집이 없으면 저장하고, 탭을 닫거나 다른 앱으로 넘어가면 바로 저장합니다. 로그인 상태 문구에 "편집하면 자동 동기화"가 붙습니다.
- 설정 메뉴의 **"지금 동기화"** 버튼은 그대로 있습니다. 다른 기기에서 고친 내용을 새로고침 없이 바로 받아오고 싶을 때 누릅니다. 누른 뒤 10초 동안은 다시 누를 수 없습니다.
- 로그인하지 않으면 예전처럼 이 브라우저에만 저장됩니다.
- 로그인에 실패하면 원인 파악을 위해 Firebase 에러 코드를 함께 보여줍니다.

## 왜 이렇게 했나
- 처음엔 저장할 때마다 자동으로 올렸지만, Firestore 무료 플랜의 일일 읽기/쓰기 쿼터를
  아끼기 위해 수동 버튼 방식으로 바꿨습니다(2026-09-27).
- 2026-11-03 다시 자동으로 바꿨습니다. 실제 로그인 사용자는 행사 당일에도 많아야 300명 정도로 예상되고(사용자 판단),
  아래처럼 쓰기를 줄이면 300명이 하루 종일 편집해도 쓰기 약 4~5천 번으로 무료 한도(하루 쓰기 2만, 읽기 5만,
  한국 시간 오후 5시 초기화)의 절반에도 못 미칩니다. 버튼을 깜빡해서 현장 폰과 PC 내용이 어긋나는 일이 더 큰 문제라고 봤습니다.
  - 글자를 칠 때마다 쓰지 않고 편집이 3초 멈추면 한 번에 씀(계속 편집 중이면 15초마다 한 번)
  - 한 기기에서 10초에 최대 1번만 씀(쓰기 횟수 상한)
  - 바뀐 게 없으면 쓰지 않음. 페이지를 열 때도 병합 결과가 클라우드와 다를 때만 씀
  - 당일만 버튼 방식으로 바꾸는 안도 검토했지만, 당일이 동기화가 가장 필요한 날이고 날짜마다 동작이 달라지면 헷갈려서 택하지 않음
- 자동 저장은 문서 전체를 덮어쓰지 않고 **바뀐 부스 항목만** 씁니다. 통째로 덮어쓰면 폰과 PC를 함께 쓸 때
  다른 기기에서 고친 다른 부스 항목이 지워질 수 있기 때문입니다(같은 부스를 두 기기에서 동시에 고치면 나중에 저장한 쪽이 남음).
- 만에 하나 한도를 넘어도 데이터는 기기(localStorage)에 남아 있고, 다음 편집이나 다음 접속 때 다시 올라갑니다.
- 병합 시 같은 부스에 로컬과 클라우드 값이 둘 다 있으면 **로컬을 우선**합니다.
  방금 이 기기에서 한 작업을 덮어쓰지 않기 위해서입니다.
- 행사장처럼 네트워크가 불안정해도 저장은 항상 localStorage에 먼저 되고,
  클라우드는 실패해도 무시하는 best-effort 방식입니다.
- 로그아웃 상태에서도 동기화 버튼은 숨기지 않고 비활성화만 해서 기능이 있다는 걸 알 수 있게 했습니다.

## 어떻게 구현했나
- Firebase compat SDK(app/auth/firestore), 설정값 `firebaseConfig` (웹 설정값은 공개 값)
- SDK 불러오기: `<script>` 태그 대신 `FIREBASE_SDK_URLS`를 코드로 끼워 넣어 백그라운드에서 받고(`async = false`로 app → auth → firestore 순서 유지),
  다 받으면 `firebaseLoaded` 프로미스가 `true`로 끝나면서 초기화·`onAuthStateChanged` 등록을 함. 실패하면 `false`.
  예전처럼 태그로 넣으면 SDK(압축 약 150KB)를 다 받을 때까지 부스 목록을 그리지 못해, 행사장처럼 회선이 붐비면 목록이 한참 안 떴음.
  그래서 로그인 버튼은 SDK를 다 받은 뒤에 나타납니다.
- 로그인/로그아웃: `signInWithGoogle()`, `signOutUser()`, UI 갱신 `updateAuthUI()`
- 데이터: Firestore `users/<uid>` 문서의 `furstclass` 필드에 `{ notes, visitStatus, budgets, spent, priority, preorders, hiddenPosts }`(`hiddenPosts`=숨긴 상품 정보 글, 2026-10-26 추가. 복구한 글은 지우지 않고 `0`으로 남겨 로컬 우선 병합에서도 복구가 전해지게 함. `spent`=쓴 돈, 2026-10-18 추가. 예전 버전 사이트는 이 필드를 모르므로, 예전 화면을 연 기기에서 동기화하면 쓴 돈이 빠진 채 올라갈 수 있음).
  동기화할 때 문서 전체를 덮어쓰므로 케모켓 때 문서 최상위에 있던 필드는 첫 동기화에서 지워집니다.
- 병합: `mergeField(local, cloud)` = `Object.assign({}, cloud, local)`
- 흐름: `syncFromCloudOnLogin()` → `pullAndMergeFromCloud()` → `pushToCloud()`
- 흐름 공통 부분: `pullMergePush()` = 받아서 병합(`pullAndMergeFromCloud()`가 클라우드와 달라졌는지 돌려줌) → 다를 때만 `pushToCloud()`(통째로 `set`) → 기준점 갱신
- 자동 저장: 저장 함수(`saveNotes()`·`saveVisitStatus()`·`saveBudgets()`·`saveSpent()`·`savePriority()`·`savePreorders()`·`saveHiddenPosts()`) 끝에서 `scheduleCloudSave()`를 부름 → 타이머 뒤 `flushCloudSave()`
  - 상수: `AUTO_SYNC_IDLE_MS = 3000`, `AUTO_SYNC_MAX_WAIT_MS = 15000`, `AUTO_SYNC_MIN_INTERVAL_MS = 10000`, 실패 시 재시도 `AUTO_SYNC_RETRY_MS = 30000`
  - 기준점 `autoSync.snapshot`: 마지막으로 클라우드와 맞춘 값. `buildCloudUpdates()`가 이것과 비교해 바뀐 `furstclass.<필드>.<부스id>`만 `FieldPath`로 모아 `update()`(지운 항목은 `FieldValue.delete()`)
  - 문서가 없으면(`not-found`) `pushToCloud()`로 새로 만듦. 로그인 병합이 아직 안 됐으면(`snapshot === null`) 병합부터 다시 함
  - `visibilitychange`(hidden)·`pagehide` 때 `flushCloudSaveNow()`로 바로 저장
  - `autoSync`는 `var`로 선언: 페이지 로드 중 데이터 정리 단계에서 저장 함수가 이 코드보다 먼저 불려도 오류 없이 건너뛰게 하기 위함
  - 로그인 계정이 바뀌거나 로그아웃하면 기준점·예약된 저장을 버림. 데이터 초기화는 클라우드를 비운 뒤 기준점도 빈 값으로 맞춤
- 수동 동기화: `syncNow()`(= `pullMergePush()`), 쿨다운 `SYNC_COOLDOWN_SECONDS = 10`, `startSyncCooldown()`

## 확인 방법
1. PC 브라우저에서 로그인 → 메모 몇 개 작성 → 버튼을 누르지 않고 5초쯤 기다림
2. 다른 브라우저(또는 시크릿 창, 휴대폰)에서 같은 계정으로 로그인 → 메모가 보이는지 확인
2-1. 두 기기에서 서로 다른 부스를 고친 뒤 각각 새로고침 → 양쪽 내용이 모두 남아 있는지 확인
2-2. F12 → Network에서 `firestore.googleapis.com` 요청을 보며 메모를 빠르게 여러 글자 입력 → 입력 중에는 요청이 없고 멈춘 뒤 한 번만 나가는지 확인
3. "지금 동기화" 직후 버튼에 남은 초가 표시되고 10초 뒤 다시 활성화되는지 확인
4. 로그아웃 상태에서 버튼이 비활성화되어 있는지 확인
5. F12 → Network → 회선 속도를 "Slow 3G"로 바꾸고 새로고침 → 로그인 버튼보다 부스 목록이 먼저 뜨는지, 잠시 뒤 로그인 버튼이 나타나는지 확인
