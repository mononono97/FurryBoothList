# Google 로그인과 동기화

## 무엇을 하나
- 톱니바퀴 옆의 로그인 버튼으로 Google 로그인하면 메모·방문 상태·예산·우선순위를 여러 기기에서 같이 쓸 수 있습니다.
- 로그인 순간 1회 자동으로 클라우드 데이터와 병합합니다.
- 로그인 중 "데이터 초기화"는 클라우드 데이터도 지웁니다(경고 후). 자세한 내용은 [설정 메뉴와 초기화](기능-설정-메뉴와-초기화.md).
- 그 뒤에는 설정 메뉴의 **"지금 동기화"** 버튼을 눌러야만 동기화됩니다. 누른 뒤 10초 동안은 다시 누를 수 없습니다.
- 로그인하지 않으면 예전처럼 이 브라우저에만 저장됩니다.
- 로그인에 실패하면 원인 파악을 위해 Firebase 에러 코드를 함께 보여줍니다.

## 왜 이렇게 했나
- 처음엔 저장할 때마다 자동으로 올렸지만, Firestore 무료 플랜의 일일 읽기/쓰기 쿼터를
  아끼기 위해 수동 버튼 방식으로 바꿨습니다(2026-09-27).
- 병합 시 같은 부스에 로컬과 클라우드 값이 둘 다 있으면 **로컬을 우선**합니다.
  방금 이 기기에서 한 작업을 덮어쓰지 않기 위해서입니다.
- 행사장처럼 네트워크가 불안정해도 저장은 항상 localStorage에 먼저 되고,
  클라우드는 실패해도 무시하는 best-effort 방식입니다.
- 로그아웃 상태에서도 동기화 버튼은 숨기지 않고 비활성화만 해서 기능이 있다는 걸 알 수 있게 했습니다.

## 어떻게 구현했나
- Firebase compat SDK(app/auth/firestore), 설정값 `firebaseConfig` (웹 설정값은 공개 값)
- SDK 불러오기: `<script>` 태그 대신 `FIREBASE_SDK_URLS`를 코드로 끼워 넣어 백그라운드에서 받고(`async = false`로 app → auth → firestore 순서 유지),
  다 받으면 `firebaseLoaded` 프로미스가 `true`로 끝나면서 초기화·`onAuthStateChanged` 등록을 함. 실패하면 `false`.
  예전처럼 태그로 넣으면 SDK(압축 약 150KB)를 다 받을 때까지 부스 목록을 그리지 못해, 행사장처럼 회선이 붐비면 목록이 한참 안 떴음.
  그래서 로그인 버튼은 SDK를 다 받은 뒤에 나타납니다.
- 로그인/로그아웃: `signInWithGoogle()`, `signOutUser()`, UI 갱신 `updateAuthUI()`
- 데이터: Firestore `users/<uid>` 문서의 `furstclass` 필드에 `{ notes, visitStatus, budgets, priority, preorders }`.
  동기화할 때 문서 전체를 덮어쓰므로 케모켓 때 문서 최상위에 있던 필드는 첫 동기화에서 지워집니다.
- 병합: `mergeField(local, cloud)` = `Object.assign({}, cloud, local)`
- 흐름: `syncFromCloudOnLogin()` → `pullAndMergeFromCloud()` → `pushToCloud()`
- 수동 동기화: `syncNow()`, 쿨다운 `SYNC_COOLDOWN_SECONDS = 10`, `startSyncCooldown()`

## 확인 방법
1. PC 브라우저에서 로그인 → 메모 몇 개 작성 → "지금 동기화"
2. 다른 브라우저(또는 시크릿 창)에서 같은 계정으로 로그인 → 메모가 보이는지 확인
3. "지금 동기화" 직후 버튼에 남은 초가 표시되고 10초 뒤 다시 활성화되는지 확인
4. 로그아웃 상태에서 버튼이 비활성화되어 있는지 확인
5. F12 → Network → 회선 속도를 "Slow 3G"로 바꾸고 새로고침 → 로그인 버튼보다 부스 목록이 먼저 뜨는지, 잠시 뒤 로그인 버튼이 나타나는지 확인
