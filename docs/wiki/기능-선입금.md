# 선입금

## 무엇을 하나
- 부스 상세 창의 **🟡 방문 예정 · 🟢 방문 완료** 옆에 **💳 선입금** 버튼이 생겼습니다.
  선입금을 받는 부스에서 이 버튼을 켜 두면 됩니다. 방문 상태와는 따로 켜고 끕니다.
- 상단 탭에 **💳 선입금** 탭이 생겼습니다(메모 탭 오른쪽). 선입금을 켠 부스만 보이고,
  탭 이름 옆 숫자가 선입금 부스 수입니다.
  - 제목 옆에 "선입금 부스 n개 · 수령 완료 m개 · 합계 ₩금액"이 표시됩니다.
  - 카드 아래에 "✅ 수령 완료" 또는 "⏳ 수령 전"과 적어 둔 금액(항목 합계)이 보입니다.
    선입금 항목이 둘 이상이면 "⏳ 수령 전 1/3건 · ₩60,000"처럼 몇 건 중 몇 건을 받았는지도 보입니다.
    모든 항목을 받아야 "✅ 수령 완료"이고, 제목 줄의 "수령 완료 m개"도 그런 부스 수입니다.
  - 검색과 우선순위순 정렬은 다른 탭처럼 그대로 됩니다.
- 선입금 탭에서 부스를 누르면 **선입금 창**이 열립니다. 부스 이름, 상품 정보(또는 부스컷),
  부스원 목록은 일반 상세 창과 같고, 그 아래에 다음이 있습니다.
  PC에서는 창 대신 카드 줄 아래에 펼쳐지며, 왼쪽에 큰 부스 번호·이름과 부스컷, 오른쪽 위에 가로로 늘어놓은 부스원, 그 아래에 아래 칸들이 옵니다
  ([부스 목록과 부스 상세 창](기능-부스-목록과-팝오버.md)).
  - **선입금 항목(2026-11-02)**: 한 부스에서 선입금을 여러 번 할 수 있어 항목 단위로 적습니다.
    항목마다 "선입금 1", "선입금 2" 번호와 아래 칸이 있고, 맨 아래 **＋ 선입금 항목 추가** 버튼으로 항목을 늘립니다(최대 30건).
    - **📦 수령 완료로 표시 / ✅ 선입금 수령 완료** 버튼(항목마다 따로, 누를 때마다 바뀜)
    - 선입금 날짜(달력), 선입금 플랫폼, 선입금 금액(원), 선입금 입금자명
    - 선입금 메모(품목 등 기타 내용, 여러 줄, 최대 1000자)
  - 항목이 둘 이상이면 맨 위에 "선입금 n건 · 수령 완료 m건 · 합계 ₩금액"이 보이고, 항목마다 **삭제** 버튼이 생깁니다.
    내용을 적어 둔 항목을 지울 때는 확인창이 먼저 뜹니다. 항목이 하나뿐이면 삭제 버튼이 없고, 선입금 자체를 끄려면 💳 버튼을 씁니다.
  - 적는 즉시 저장되어 따로 저장 버튼이 없습니다.
- 정보를 적어 둔 부스에서 💳 선입금 버튼을 끄면, 적어 둔 정보가 같이 지워진다는 확인창이 먼저 뜹니다
  (기본 포커스는 취소). 아무것도 적지 않았으면 바로 꺼집니다.
- **배치도 탭의 💳 선입금 보기**: 배치도 위 "🗺️ 기본 보기 / 💳 선입금 보기" 버튼으로 바꿉니다.
  선입금 보기에서는 선입금 수령 전 부스(항목 중 하나라도 안 받은 부스)는 노랑, 모든 항목을 받은 부스는 초록, 선입금이 없는 부스는 흐리게 보입니다.
  선입금 부스를 누르면 선입금 창(선입금 메모 포함)이, 그 밖의 부스는 일반 상세 창이 열립니다. 고른 보기는 새로고침해도 유지됩니다.
- Google 로그인 동기화와 "데이터 초기화"에도 포함됩니다.

## 왜 이렇게 했나
- 2026-10-05 사용자 요청: 선입금을 진행하는 부스가 있어, 방문 예정/완료 옆에 선입금 버튼을 두고
  선입금 부스만 모아 보는 탭과 수령 여부·날짜·플랫폼·금액·입금자명을 적는 창을 원함.
- 선입금 창에는 방문 상태·우선순위·예산·메모를 넣지 않았습니다. 선입금 탭에서는
  선입금 정보만 보는 것이 목적이라 요청대로 부스 정보·부스원 아래에 선입금 칸만 둡니다.
  방문 상태 등은 다른 탭에서 부스를 열면 그대로 바꿀 수 있습니다.
- 선입금 정보는 메모·방문 상태·예산과 같은 방식(브라우저 저장 + 로그인 시 수동 동기화)으로 저장합니다.
- 선입금 금액은 예산과 따로 셉니다. 예산은 "쓸 계획", 선입금은 "이미 낸 돈"이라 섞지 않았습니다.
- 2026-11-02 사용자 요청: 한 부스에서 선입금을 여러 번 할 수 있으니 "항목 추가"로 여러 건을 적게 해 달라고 함.
  날짜·플랫폼·금액·입금자명·메모·수령 여부가 건마다 다를 수 있어서 칸 묶음 전체를 항목으로 반복합니다.
  부스 단위 표시(카드·배치도 색·탭 숫자)는 그대로 두고, 금액은 합계, 수령 완료는 "모든 항목을 받았을 때"로 정했습니다.
  하나라도 안 받았으면 행사장에서 그 부스에 들러야 하니 노랑(수령 전)으로 남기는 편이 맞기 때문입니다.
- 이미 적어 둔 선입금은 그대로 "선입금 1"이 됩니다(아래 구현의 자동 변환). 사라지거나 다시 적을 필요가 없습니다.
- 끌 때 확인창을 두는 이유: 버튼 한 번 잘못 눌러 입금자명·금액 같은 기록이 사라지지 않게 하기 위해서입니다.

## 어떻게 구현했나 (`index.html`)
- localStorage 키 `furstclass-preorder` (2026-11-02부터 항목 목록):
  `{ "A01": { items: [ { received: true, date: "2026-11-01", platform: "위치폼", amount: 35000, payer: "홍길동", memo: "아크릴 스탠드 1" }, { received: false, amount: 20000 } ], received: false, amount: 55000 } }`.
  부스가 이 객체에 있으면 선입금이 켜진 것입니다. 빈 칸은 저장하지 않습니다.
  - 위쪽 `received`(모든 항목 수령)·`amount`(합계)는 `savePreorders()`가 저장할 때마다 다시 계산해 적는 요약입니다.
    새로고침 전의 예전 화면(다른 기기 등)이 이 데이터를 받아도 카드의 수령 여부·금액은 맞게 보이게 하려는 것이고, 지금 화면은 `items`만 읽습니다.
  - 예전 모양(`{ received, date, platform, amount, payer, memo }`)은 `normalizePreorder()`가 항목 하나짜리로 바꿉니다.
    사이트를 열 때와 클라우드와 합친 뒤(`pullAndMergeFromCloud()`) `migratePreorderShape()`가 저장값 전체를 바꿔 두고,
    `getPreorder()`도 읽을 때 한 번 더 확인합니다. 그래서 예전 기기의 데이터가 동기화로 들어와도 사라지지 않습니다.
- 함수: `loadPreorders()`, `savePreorders()`, `getPreorder()`, `getPreorderItems()`, `setPreorderOn()`,
  `addPreorderItem()`, `removePreorderItem()`, `setPreorderField(boothId, index, field, value)`,
  `preorderHasDetails()`(항목이 둘 이상이거나 적은 내용이 있으면 true), `preorderItemHasDetails()`,
  `isPreorderReceived()`, `getPreorderAmount()`, `getPreorderTotal()`. 항목은 최대 `MAX_PREORDER_ITEMS`(30)건. 글자 칸은 최대 `MAX_PREORDER_TEXT`(100)자, 선입금 메모는 일반 메모와 같은 `MAX_NOTE_LENGTH`(1000)자.
- 탭: `renderNav()`의 💳 버튼 → `goToRow("PREORDER")`, `VALID_ROWS`에 `PREORDER` 추가.
  `renderGrid()`의 `isPreorderView`가 목록·제목·카드의 `.preorder-line`을 그립니다.
- 창: 일반 상세 창과 공통인 윗부분을 `openBoothModalShell()`로 떼어 냈고,
  `openBoothModal()`(일반)과 `openPreorderModal()`(선입금)이 같이 씁니다. 창을 띄우는 부분은 `showBoothModal()`.
  선입금 탭 카드를 누르면 `openPreorderModal()`, 다른 탭과 배치도에서는 지금처럼 `openBoothModal()`.
  2026-10-05부터 칸 내용은 `fillPreorderActions()`로 만들고(2026-11-02부터 항목마다 `.preorder-item`, 추가 버튼 `.preorder-add-btn`,
  항목을 추가·삭제하면 칸 전체를 다시 그림), PC 카드 클릭은 `openInlineDetail(id, "preorder")`가
  같은 함수로 오른쪽 칸을 채웁니다. 수령 완료·칸 수정으로 `renderGrid()`가 다시 돌아도 펼친 상세는 유지됩니다.
- 동기화: `pushToCloud()`가 `preorders`도 올리고, `pullAndMergeFromCloud()`가 부스 단위로 합칩니다
  (같은 부스는 이 기기 값 우선, 다른 데이터와 같은 규칙). 두 칸 부스 번호 이전(`migrateAllMergedBoothIds()`)과
  `resetAllData()`에도 포함.
- 배치도: `mapMode`("basic"/"preorder", 저장 키 `furstclass-map-mode`), `setMapMode()`, `openMapBooth()`.
  선입금 보기에서는 `buildMapSvg()`가 수령 전에 `visit-planned`, 수령 완료(`isPreorderReceived()`)에 `visit-visited` 클래스를 붙여 기존 노랑·초록 색을 그대로 쓰고, 선입금이 없는 부스는 `.dim`(흐리게).
- 색: 일반 창의 💳 버튼 켜짐은 청록(`#2f8f8a`), 카드의 "수령 완료" 글자는 테마 토큰 `--preorder-done`.

## 확인 방법
1. PC 브라우저로 사이트를 열고 아무 부스나 누름 → 방문 예정·방문 완료 오른쪽에 "💳 선입금" 버튼이 있는지
2. 💳 선입금을 누르면 버튼이 청록색이 되고 상단 탭이 "💳 선입금(1)"로 바뀌는지
3. 💳 선입금 탭 → 그 부스만 보이고 카드에 "⏳ 수령 전"이 있는지
4. 카드를 누름 → 부스 정보·부스원 아래에 수령 완료 버튼과 날짜·플랫폼·금액·입금자명·선입금 메모 칸이 있는지
5. 칸을 채우고 수령 완료를 누른 뒤 창을 닫음 → 카드가 "✅ 수령 완료 · ₩금액", 제목 줄 합계가 맞는지
6. 새로고침해도 그대로인지, 다른 탭에서 그 부스를 열어 💳 선입금을 끄려 하면 확인창이 뜨는지(취소하면 유지)
7. 배치도 탭 → "💳 선입금 보기" → 수령 전 부스는 노랑, 수령 완료는 초록인지, 선입금 부스를 누르면 선입금 메모가 있는 선입금 창이 뜨는지
8. 선입금 창 맨 아래 "＋ 선입금 항목 추가"를 누름 → "선입금 2" 칸이 생기고, 맨 위에 "선입금 2건 · 수령 완료 n건 · 합계"가 보이는지
9. 두 번째 항목에 금액을 적음 → 합계와 선입금 탭 카드 금액이 두 항목을 더한 값인지, 카드에 "1/2건"처럼 보이는지
10. 한 항목만 수령 완료면 카드가 "⏳ 수령 전"·배치도 노랑, 모두 수령 완료면 "✅ 수령 완료"·초록인지
11. 내용을 적은 항목의 "삭제"를 누름 → 확인창이 뜨고, 삭제하면 그 항목만 없어지는지(취소하면 그대로)
12. 이번 변경 전에 적어 둔 선입금이 있었다면 그 내용이 "선입금 1"로 그대로 보이는지
13. 로그인 상태라면 "지금 동기화" 후 다른 기기에서도 동기화해서 선입금 정보가 보이는지
