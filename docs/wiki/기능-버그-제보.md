# 버그 제보

## 무엇을 하나
- 설정(⚙️) 메뉴의 **🐞 버그 제보**를 누르면 버그 제보 창이 열립니다(한·영·일).
- **📧 메일 앱으로 보내기**를 누르면 휴대폰·PC의 메일 앱에 개발자 주소(hwanichung04@gmail.com)로 가는 새 메일이 열립니다.
  메일 본문 맨 위에 무엇을 적으면 되는지 안내 양식이 미리 들어 있습니다.
  ```
  ■ 발생 시간
  (예: 11/28 오후 2시 30분쯤)

  ■ 상황 설명 (어느 화면에서 무엇을 했더니 어떻게 됐는지)
  (여기에 적어 주세요)

  ---- 자동으로 담긴 기록 ----
  [env] / [data] / [log] …
  ```
- 안내 양식 아래에는 버그 파악에 쓰는 기록이 자동으로 붙습니다.
  - `[env]` 제보 시각, 사이트 코드 지문(`code xxxxxxxx`), 보고 있던 탭(배치도 구역·메모 필터·펼친 부스 등), 검색어, 언어·테마, 로그인 여부(계정 정보 없이 예/아니오만), 온라인·서비스 워커 여부, 화면·창 크기, 브라우저(User-Agent), 저장 용량, 상품 글 목록을 받은 시각
  - `[data]` 메모·방문 예정/완료·우선순위·예산·쓴 돈·선입금(부스/항목/수령)·숨긴 글의 **개수**
  - `[log]` 최근 기록 40건(최신이 위): JS 오류, 처리 안 된 Promise 오류, `console.error/warn`, 스크립트 받기 실패, 탭 이동, 부스 상세·선입금 창 열기, 동기화 성공/실패(오류 코드), 로그인/로그아웃
  - `[raw data]` "데이터 원본도 기록에 넣기"를 체크했을 때만 메모·선입금 등 저장한 데이터 원본(JSON)
- 창의 "메일에 함께 들어가는 기록 보기"를 펼치면 보낼 기록을 그대로 미리 볼 수 있고, 메일 앱에서 보내기 전에 고치거나 지울 수도 있습니다.
- 메일 앱이 열리지 않을 때(PC에 메일 프로그램이 없을 때 등)를 위한 다른 방법
  - **Gmail로 보내기**: 새 탭에 Gmail 쓰기 화면을 같은 내용으로 엶
  - **📋 메일 내용 복사**: 받는 사람·제목·본문 전체를 복사해서 쓰는 메일에 붙여 넣기
  - **💾 기록 파일 저장**: 기록 전체를 `bug-log-날짜-시간.txt` 파일로 저장(메일에 직접 첨부)
  - **📎 기록 파일로 공유**: 파일 공유를 지원하는 휴대폰 브라우저에서만 보임. 기록 파일을 첨부한 채로 메일 앱 등을 고를 수 있음(받는 사람은 직접 입력)

## 왜 이렇게 했나
- 2026-11-03 사용자 요청: 톱니바퀴에 버그 제보 버튼을 두고, 현재 데이터와 로그를 담아 개발자 메일로 보내게 함.
  이어서 "메일 본문에 발생 시간·간단한 상황 설명을 적도록 미리 안내하고, 로그는 첨부 파일로 자동 제출" 요청.
- 보내는 방식은 세 가지를 비교했고, 사용자가 **메일 앱 방식**을 골랐습니다(2026-11-03).
  | 방식 | 장점 | 단점 |
  |---|---|---|
  | 메일 앱(mailto) — **채택** | 설치·비용·키 없음, 휴대폰에서 바로 됨, 보낸 사람에게 답장 가능 | 파일 자동 첨부 불가, PC에 메일 프로그램이 없으면 안 열림, 주소 길이 제한 |
  | 사이트에서 바로 전송(Worker + 메일 API) | 로그 파일 자동 첨부 가능 | Resend 같은 메일 서비스 가입·API 키·Worker 추가 필요, 스팸 악용 대비 필요 |
  | Firestore에 쌓고 관리 화면에서 보기 | 이미 쓰는 Firebase라 비용 없음 | 메일로 오지 않음, 보안 규칙·관리 화면 추가 필요 |
- **로그를 첨부 파일로 자동 제출할 수 없는 이유**: 브라우저가 메일 앱을 여는 `mailto:` 주소에는 첨부 파일을 넣는 방법이 없습니다(표준에 없고, 보안상 메일 앱들도 막음).
  그래서 기록은 메일 본문 아래에 글로 넣고, 파일로 받고 싶은 경우를 위해 "기록 파일 저장"과 휴대폰 "기록 파일로 공유"를 둡니다.
  나중에 자동 첨부가 꼭 필요해지면 위 표의 "사이트에서 바로 전송" 방식으로 바꿔야 합니다.
- **주소 길이 제한**: PC 메일 프로그램(Outlook 등)은 약 2,000자를 넘는 `mailto:` 주소를 자르거나 아예 못 여는 경우가 있습니다.
  한국어 안내문은 주소에 넣으면 글자당 9자로 늘어나서, PC 메일 앱용 본문은 2,000자(인코딩 후)에 맞춥니다.
  넘치면 데이터 원본 → 오래된 기록 순으로 줄이고, 그래도 넘치면 최근 기록 5줄을 앞에 두고 뒷줄부터 뺀 뒤
  "기록이 길어 일부만 담았어요 … 기록 파일 저장으로 받아 첨부해 주세요" 줄을 넣습니다.
  휴대폰 메일 앱은 8,000자, Gmail 쓰기 화면은 7,000자까지 넣습니다.
- **개인 정보**: 로그인 이메일·uid·메모 내용은 기본으로 넣지 않고 개수만 넣습니다. 데이터 원본은 사용자가 체크했을 때만 들어갑니다.
  미리보기로 보낼 내용을 보여 주고, 실제 전송은 사용자가 메일 앱에서 직접 누르므로 보내기 전에 고칠 수 있습니다.
- 개발자 메일 주소는 단순 수집 봇이 소스에서 바로 긁어 가지 않도록 코드에서 나눠 적었습니다(창에는 그대로 보임).

## 어떻게 구현했나
- `index.html` `<head>`의 첫 `<script>`(테마 스크립트 아래)에서 기록을 모읍니다. 다른 스크립트보다 먼저 실행되므로 페이지를 여는 중의 오류도 잡힙니다.
  - `window.fcBugLog` = `{ add(kind, msg), all(), clear() }`
  - localStorage 키 **`fcbug-log`**: 최근 40건, 3일 지난 기록은 버림, 한 줄 300자까지, 같은 내용이 연달아 나면 `x횟수`로 묶음.
    새로고침한 뒤 제보해도 직전 오류가 남아 있게 하려고 이 기기에 저장합니다.
    키가 `furstclass-`로 시작하지 않는 이유: 첫 방문 판정(`furstclass-` 키가 하나라도 있는지)에 끼지 않게 하려고.
  - `window` `error`(캡처 단계, 스크립트 받기 실패 포함 — 이미지 실패는 흔해서 뺌), `unhandledrejection`, `console.error/warn` 감싸기
- 본문 `<script>`
  - `bugTrace(kind, msg)`: 사용 흔적 남기기. `goToRow`(tab), `openBoothModal`·`openPreorderModal`·`openInlineDetail`(open), `syncNow`·`syncFromCloudOnLogin`(sync, 실패 시 오류 코드), `onAuthStateChanged`(auth), Firebase SDK 받기 실패(firebase)
  - `BUG_REPORT_EMAIL`, `BUG_MAILTO_MAX = { desktop: 2000, mobile: 8000, gmail: 7000 }`
  - `buildBugLog({ maxLog, withRaw })` → `[env]`(`bugEnvLines`), `[data]`(`bugDataSummary`), `[log]`, `[raw data]`
  - `buildBugMailBody(log, trimmed)` → 안내 양식 + 기록, `fitBugMailBody(limit, withRaw)` → 길이 맞추기
  - `bugMailtoHref`, `bugGmailHref`: 휴대폰 여부는 `(pointer:coarse)`로 판단
  - `openBugReportModal()`: 도움말과 같은 `#modalBackdrop` 창을 씀(뒤로 가기·Esc·창 밖 클릭으로 닫힘). 기록 파일은 `Blob` 다운로드, 공유는 `navigator.canShare({ files })`일 때만
  - `codeFingerprint()`: 이 본문 `<script>` 내용의 FNV-1a 32bit 해시. 기록의 `code xxxxxxxx`
- 번역 키: `bugReportBtn`, `bugTitle`, `bugIntro`, `bugIncludeData`, `bugPreviewSummary`, `bugPrivacy`, `bugMailApp`, `bugGmail`, `bugCopy`, `bugCopied`, `bugCopyFail`, `bugDownload`, `bugShareFile`, `bugAltHint`, `bugMailOpened`, `bugMailTrimmed`, `bugMailTime`, `bugMailTimeHint`, `bugMailDesc`, `bugMailDescHint`, `bugMailLog`, `bugSubject`
- CSS: `.bug-form`, `.bug-check`, `.bug-preview`, `.bug-privacy`, `.bug-send-btn`, `.bug-status`, `.bug-alt-hint`, `.bug-alt` (패널 토큰만 써서 라이트·다크 둘 다 맞음)
- CSP 변경 없음: `mailto:`와 Gmail 링크는 페이지 이동이라 `connect-src`와 관계없습니다.
- `tools/code_fingerprint.py`: 제보에 적힌 `code` 값이 어느 커밋의 `index.html`인지 찾는 도구
  ```
  python3 tools/code_fingerprint.py              # 지금 index.html 의 지문
  python3 tools/code_fingerprint.py 645bec71     # origin/main 최근 300개 커밋 중 같은 지문 찾기
  ```

## 확인 방법
1. 사이트에서 ⚙️ → **🐞 버그 제보**를 누르면 제보 창이 열리는지 확인(KO/EN/JP를 바꿔 문구도 확인)
2. "메일에 함께 들어가는 기록 보기"를 펼쳐 `[env]`, `[data]`, `[log]`가 보이는지, 메모 내용이 들어 있지 않은지 확인
3. 탭을 몇 번 옮기고 부스를 연 뒤 다시 열면 `[log]`에 `tab:`/`open:` 줄이 쌓이는지 확인
4. "데이터 원본도 기록에 넣기"를 체크하면 미리보기 끝에 `[raw data]`가 생기는지 확인
5. **📧 메일 앱으로 보내기** → 메일 앱이 받는 사람·제목·안내 양식·기록이 채워진 채로 열리는지(휴대폰, PC 모두)
6. **Gmail로 보내기** → 새 탭에 Gmail 쓰기 화면이 같은 내용으로 열리는지
7. **💾 기록 파일 저장** → `bug-log-….txt`가 받아지는지, 휴대폰에서는 **📎 기록 파일로 공유**로 메일 앱에 첨부되는지
8. 기존 기능 확인: 우선순위 정렬, 탭 이동, 부스 상세·선입금 창, 로그인 동기화가 그대로인지
