# 오프라인 지원과 파비콘

## 무엇을 하나
- 한 번 접속한 뒤에는 인터넷이 끊겨도 사이트를 볼 수 있습니다(행사장 통신 불안정 대비).
- 처음 접속하면 백그라운드에서 목록용 부스컷 썸네일·프로필 사진(약 7MB, 2026-10-08부터. 그 전에는 원본 부스컷까지 약 13MB)을 자동으로 받아 둡니다.
  그래서 직접 열어 보지 않은 부스의 사진도 오프라인에서 보입니다(상세 창은 원본을 못 받으면 썸네일로 대신 보여줌). 따로 누를 버튼은 없습니다.
- 회선이 아주 느릴 때: 저장해 둔 페이지가 있으면 3초만 기다리고 그 페이지로 먼저 띄웁니다. 늦게 받은 최신 페이지는 다음 접속에 반영됩니다.
- 오프라인에서 안 되는 것: 부스 상세의 X 최근 글, 행사 정보 탭의 공식 공지·구글 지도·날씨,
  Google 로그인과 "지금 동기화"(메모·방문 상태·우선순위·예산은 기기에 저장되고, 온라인에서 동기화하면 올라감)
- 브라우저 탭에 파비콘이 보입니다.

## 왜 이렇게 했나
- 페이지는 **네트워크 우선**: 온라인이면 항상 최신, 오프라인이면 캐시 사용. 다만 행사장처럼 끊기지는 않고 느리기만 한 회선에서는 캐시가 있어도 응답을 기다리느라 빈 화면이었으므로(시험: 응답 10초 지연 시 목록 표시 10.1초) 3초가 지나면 캐시로 먼저 띄웁니다(같은 시험에서 3.1초, 2026-10-08).
- 오류 응답(404·500)은 페이지 캐시에 넣지 않습니다. 잠깐 난 오류 페이지가 오프라인용으로 남지 않게 하려는 것.
- 아바타 이미지는 **캐시 우선**: 한 번 본 이미지는 오프라인에서도 계속 보임
- 사진 미리 받기는 "오프라인 저장" 버튼 대신 자동으로 함(사용자 결정 2026-10-04): 행사장에서 처음 여는 사람이
  버튼을 모르고 지나치면 소용이 없기 때문. 대신 모바일 데이터로 처음 접속하면 약 7MB를 씁니다(2026-10-08 썸네일로 바꾸기 전에는 약 13MB).
- 행사 직전(2026-11-28 행사 기준 약 1주 전부터)에는 `CACHE_VERSION`을 올리거나 이미지를 같은 파일명으로 교체하지 않는 것을 권장합니다.
  버전을 올리면 모든 방문자의 캐시가 지워져 행사장 회선에서 사진을 모두 다시 받게 됩니다. (2026-10-05 접속자 1000명 점검 때 권장)
- 파비콘을 `favicon.ico`로 저장했는데 실제로는 PNG라 브라우저가 표시하지 못해 `favicon.png`로 바꿨습니다.

## 어떻게 구현했나
- `sw.js`: 캐시 이름 `furstclass-cache-v5` (`CACHE_VERSION`, 케모켓 때는 `kemoket-cache-v1`).
  부스컷(`booth-cuts/`, 썸네일 `booth-cuts/thumbs/` 포함)도 아바타처럼 캐시 우선, 404 응답은 캐시하지 않음. 캐시 구조를 바꾸면 버전을 올려 이전 캐시를 지웁니다.
- 페이지 요청: 캐시가 있으면 `Promise.race([네트워크, NETWORK_TIMEOUT_MS(3000) 뒤 캐시])`, 캐시가 없으면(첫 방문) 네트워크를 끝까지 기다림. 받은 응답은 `response.ok` 일 때만 캐시하고, `event.waitUntil` 로 캐시로 먼저 띄운 뒤에도 저장을 마침.
- 사진 미리 받기: `index.html`의 `allImageUrls()`가 `BOOTHS`에서 부스컷 썸네일(`boothThumbUrl`, 2026-10-08 전에는 원본 `boothCutUrl`)과 부스·부스원 프로필
  사진(`localAvatarUrl`) 경로를 모아 서비스 워커에 `precache-images` 메시지로 보냄(접속할 때마다).
  `sw.js`의 `precacheImages()`가 4개씩 동시에 받아 캐시에 넣고, 이미 있는 것은 건너뜀.
  받는 중 인터넷이 끊기면 멈추고 다음 접속 때 남은 것부터 받음. 404는 캐시하지 않음.
- 이미지 캐시 조회는 `ignoreVary: true`(미리 받은 요청과 `<img>` 요청의 헤더가 달라도 같은 이미지로 찾기 위해)
- CSP에 `worker-src 'self'` 추가

## 확인 방법
1. 사이트 접속 → 개발자 도구(F12) → Application → Service Workers에서 등록 확인
2. Application → Cache storage → `furstclass-cache-v5`에 `booth-cuts/thumbs/`(99개), `avatars/`(167개) 이미지가 들어 있는지 확인
4. Network 탭에서 속도를 "Slow 3G"보다 느리게(또는 Custom으로 지연 10초) 하고 새로고침 → 약 3초 뒤 목록이 뜨는지 확인
3. Network 탭에서 Offline 체크 후 새로고침 → 사이트가 뜨는지, 전체 탭에서 B·C구역 부스컷까지 다 보이는지 확인
