# 사용법 설명서 드라이브 자동 업로드

## 무엇을 하나
- 사용법 설명서 PDF(한국어·영어·일본어판)를 저장소 `docs/guide/`에 넣은 PR이 main에 병합되면,
  GitHub Actions가 구글 드라이브의 **기존 설명서 파일에 새 버전으로** 올립니다.
- 새 파일을 만드는 게 아니라 같은 파일의 내용만 바뀌므로 드라이브 공유 링크와 사이트 도움말의
  "📖 사용법 설명서 보기" 버튼은 그대로이고, 이전 판은 드라이브의 **버전 관리**에 남습니다.
- 사람이 할 일은 설명서 PR을 확인하고 병합하는 것뿐입니다(병합 = 업로드 승인).

| 언어 | 저장소 파일 | 드라이브 파일 |
|---|---|---|
| 한국어 | `docs/guide/Furst-Class-부스목록-사용법.pdf` | `HELP_GUIDE_URL.ko` |
| 영어 | `docs/guide/Furst-Class-Booth-List-Guide-EN.pdf` | `HELP_GUIDE_URL.en` |
| 일본어 | `docs/guide/Furst-Class-Booth-List-Guide-JP.pdf` | `HELP_GUIDE_URL.jp` |

## 왜 이렇게 했나
- 지금까지는 설명서를 고칠 때마다 사용자가 드라이브에서 세 파일에 손으로 "새 버전 업로드"를 해야 했습니다.
- 드라이브 커넥터(Claude 쪽)는 새 파일 만들기 위주라 기존 파일의 새 버전 올리기가 확실하지 않고,
  5MB 가까운 PDF를 대화로 넘기기도 어려워 쓰지 않았습니다.
- 서비스 계정 키로 GitHub Actions에서 올리면 사람이 PC를 켜 둘 필요가 없고, PDF가 저장소에 들어가서
  git 기록으로도 판이 남습니다. `docs/`는 `.assetsignore`로 사이트 배포에서 빠져 있어 사이트 용량은 그대로입니다.
- 버전마다 `keepRevisionForever`를 켜서, 드라이브가 30일 지난 옛 버전을 자동으로 지우지 않게 했습니다.
- 드라이브 쪽 내용(md5)이 이미 같으면 건너뛰어, Run workflow를 다시 눌러도 같은 버전이 쌓이지 않습니다.

## 어떻게 구현했나
- 워크플로: `.github/workflows/upload-guide-to-drive.yml` (main에 `docs/guide/*.pdf`가 바뀌어 들어올 때, 또는 Actions 탭 Run workflow)
  - Run workflow 입력: `only`(ko,en,jp 중 일부), `dry_run`(올리지 않고 대상만 출력)
- 스크립트: `tools/upload_guide_to_drive.py`
  - 드라이브 파일 ID는 `index.html`의 `HELP_GUIDE_URL`에서 읽음(사이트 링크와 업로드 대상이 항상 같음).
    드라이브 파일을 바꾸면 `HELP_GUIDE_URL`만 고치면 됨.
  - Drive API v3 `files.update` 재개 가능 업로드(5MB 넘어도 됨), `keepRevisionForever=true`. 올린 뒤 md5를 저장소 파일과 비교.
- 비밀값: GitHub 저장소 Actions 비밀값 `GDRIVE_SA_KEY` (서비스 계정 JSON 키 전체). 위키에는 적지 않음.
- 서비스 계정은 드라이브 용량이 없어 새 파일을 만들 수 없지만, 사용자 소유 파일을 "편집자"로 공유받아
  내용을 바꾸는 것은 됩니다(용량은 파일 소유자 기준).

### 처음 한 번 설정 (사용자)
1. https://console.cloud.google.com 에서 프로젝트를 하나 만들고(이름 자유, 예: furryboothlist-guide),
   "API 및 서비스 → 라이브러리"에서 **Google Drive API**를 사용 설정.
2. "IAM 및 관리자 → 서비스 계정 → 서비스 계정 만들기"(역할은 주지 않아도 됨). 만든 계정의 이메일
   (`…@….iam.gserviceaccount.com`)을 복사.
3. 그 서비스 계정 → "키" 탭 → 키 추가 → 새 키 만들기 → JSON. 내려받은 파일이 키(비밀번호처럼 보관).
4. 구글 드라이브에서 설명서 세 파일(한·영·일)을 각각 공유 → 2번 이메일을 **편집자**로 추가(알림 보내기는 꺼도 됨).
5. GitHub 저장소 → Settings → Secrets and variables → Actions → New repository secret,
   이름 `GDRIVE_SA_KEY`, 값에 3번 JSON 파일 내용을 통째로 붙여넣기.
6. Actions 탭 → "사용법 설명서 드라이브 업로드" → Run workflow(`dry_run` 체크)로 설정 확인.

## 확인 방법
1. 설명서 PDF를 `docs/guide/`에 넣은 PR을 main에 병합
2. GitHub Actions 탭에서 "사용법 설명서 드라이브 업로드" 실행이 초록색인지, 로그에 `[ko] '…' 새 버전 업로드 완료`가 있는지 확인
3. 드라이브에서 파일 → 우클릭 → 파일 정보 → **버전 관리**에 새 버전(서비스 계정 이름)이 생겼는지,
   사이트 도움말의 설명서 버튼이 새 판을 여는지 확인(드라이브 미리보기는 몇 분 늦게 바뀔 수 있음)
4. 실패하면 로그 마지막 줄에 이유가 나옴: 비밀값 없음 / 파일을 볼 수 없음(공유 안 됨) / 편집 권한 없음
