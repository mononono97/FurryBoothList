# 부스 상품 정보 (X 글 후보 수집과 관리 화면)

## 무엇을 하나
- 부스장 X 계정이 올린 글 중 **상품 글 같아 보이는 글**을 1시간마다 자동으로 모아 후보로 쌓습니다.
- 운영자는 관리 화면(`admin.html`, 사이트 주소 뒤에 `/admin.html`)에서 후보를 보고 **반영** 또는 **제외**를 누릅니다.
- 반영한 글은 사이트의 부스 상세 창에 **"상품 정보"** 제목 아래 X 글 모양으로 바로 나타납니다. 다시 배포할 필요가 없습니다.
- 반영된 글이 있는 부스는 상세 창 맨 위의 **부스컷 대신** 상품 정보 글이 보입니다. 반영된 글이 없는 부스는 지금처럼 부스컷이 보입니다.
- 후보에 없는 글(키워드가 없는 상품 글 등)은 관리 화면의 **"글 주소로 직접 추가"** 칸에 X 글 주소를 붙여 넣어 반영할 수 있습니다.
- 반영됨·제외됨 탭에서 **"대기로 되돌리기"**를 누르면 결정을 취소합니다.
- 관리 화면은 운영자 계정으로 로그인해야 목록이 보입니다. 로그인하지 않았거나 다른 계정이면 "관리 권한이 없습니다"만 보입니다.
- X가 **민감한 내용**으로 표시한 글은 X가 임베드를 막아("Not found") 사이트에서 X 글 모양 대신 **본문과 "X에서 보기" 링크만 있는 카드**로 보입니다.
  관리 화면 후보에는 "민감한 글" 표시가 붙고, "사이트에 보일 모양"도 그 카드로 보여줍니다.
- 다른 글을 **인용한 글**은 인용된 글을 빼고 보여주기 위해, X 글 모양 대신 **본문과 이미지가 있는 카드**로 보입니다.
- 위쪽 탭의 **🆕 최근 갱신** 탭은 반영된 상품 정보 글이 있는 부스만, 가장 최근 글이 올라온 부스부터 보여줍니다. 카드 아래에 "10/4 갱신"처럼 그 글을 올린 날짜가 붙습니다.

## 왜 이렇게 했나
- 작가들에게 해시태그를 정해서 올려 달라고 하기 어렵다는 사용자 의견(2026-10-04)에 따라, 평소 글에서 자동으로 골라내고
  사람이 마지막에 확인하는 방식으로 정했습니다.
- **판단 방식**: 사용자 결정(2026-10-04)으로 무료인 키워드 점수로 시작하고, 정확도가 아쉬우면 나중에 AI(Claude API) 판단을 붙입니다.
  어차피 운영자가 최종 확인하므로 조금 넓게 잡아도 괜찮습니다.
- **X 공식 API를 쓰지 않은 이유**: 글 읽기가 유료입니다. 대신 행사 안내 탭에서 이미 쓰는 FxTwitter 공개 JSON(무료·키 없음)을 씁니다.
- **방문자 브라우저가 아니라 GitHub Actions가 모으는 이유**: 부스장 계정이 약 100개라 방문자마다 조회하면 느리고 FxTwitter 제한에 걸리기 쉽습니다.
  클라우드 개발 환경에서는 FxTwitter가 막혀 있지만 GitHub Actions에서는 열려 있음을 2026-10-04에 확인했습니다.
- **후보를 main이 아니라 `x-post-feed` 브랜치에 쌓는 이유**: main에 커밋할 때마다 Cloudflare가 사이트를 다시 배포하기 때문입니다.
- **반영 목록을 Firestore에 두는 이유**: 관리 화면에서 누르는 즉시 사이트에 반영되고, GitHub 토큰 같은 비밀값 없이
  이미 쓰고 있는 Google 로그인만으로 운영자를 구분할 수 있습니다.
- **운영자 UID를 코드에 넣지 않은 이유**: 공개 저장소라서입니다. 관리 화면은 운영자만 읽을 수 있게 규칙을 건
  `boothPosts/admin` 문서를 읽어 보고, 권한 오류가 나면 목록을 숨깁니다(사용자 요청, 2026-10-04).
  후보 파일 자체는 GitHub 공개 저장소에 있으므로 완전히 숨기는 것은 아닙니다. 보이는 내용은 원래 X에 공개된 글입니다.
- **민감한 글을 카드로 보여주는 이유**: X 임베드는 민감한 글(`possibly_sensitive`)에 대해 `TweetTombstone`을 돌려줘
  "Not found"만 보이고 `createTweet()`도 끝나지 않습니다(2026-10-04 GitHub Actions 브라우저로 확인, B-11·B-02 글).
  이미지는 민감한 내용일 수 있어 사이트에 넣지 않고 X 링크로 보냅니다.
- **인용 글을 카드로 보여주는 이유**: X 임베드 옵션에는 인용 글을 숨기는 방법이 없습니다. `cards: "hidden"`은 인용 글은 그대로 두고
  첨부 이미지만 링크로 바꿔 버립니다(2026-10-04 GitHub Actions 브라우저로 확인). 그래서 인용 글이 있는 글은 직접 카드로 그립니다(사용자 요청, 2026-10-04).

## 어떻게 구현했나
- **후보 수집**: `tools/collect_booth_posts.py`
  - `index.html`의 `const BOOTHS = ...;` 줄에서 부스장 X 아이디(`booth.twitter`)만 읽고, 잠금 계정(`data/x-protected-handles.txt`)은 뺍니다.
  - 아이디마다 `https://api.fxtwitter.com/2/profile/<소문자 아이디>/statuses`로 최근 글 약 20개를 받습니다.
    FxTwitter는 가끔(대문자 아이디일 때 특히 자주) 빈 결과(404)를 줘서, 소문자 → 원래 표기 순서로 2번씩 다시 시도합니다.
  - 리트윗·답글·다른 사람 글·`POST_SINCE`(2026-09-21, 케모켓 다음 날. 같은 작가들의 케모켓 인포 글이 섞이지 않게) 이전 글을 거르고, `judge()`로 점수를 매겨 `MIN_SCORE`(2) 이상이면 후보로 넣습니다.
  - 점수: `KEYWORDS`(한국어·일본어·영어)에서 인포/신간 3점, 통판·예약/굿즈·판매/가격 2점, 품목 이름/행사·부스 1점, 키워드가 하나라도 걸린 글에 이미지가 있으면 1점.
    t.co 링크 안의 글자가 키워드(예: 부스 번호)로 잡히지 않도록 링크는 지우고 판단합니다.
  - 결과: `candidates.json`의 `posts` 배열 (`id`, `handle`, `booths`, `boothNames`, `created`, `text`, `images`, `score`, `reasons`, `sensitive`, `quote`, `foundAt`).
    새 후보가 없으면 파일을 건드리지 않습니다. AI 판단은 `judge()` 안에 붙이면 됩니다.
- **정기 실행**: `.github/workflows/collect-booth-posts.yml`, 매시 17분 + Actions 탭의 "Run workflow"로 수동 실행.
  main에서 실행될 때만 `x-post-feed` 브랜치에 커밋하고, 다른 브랜치에서는 `--dry-run`으로 결과만 출력합니다.
  부스장 계정 약 100개를 1초 간격으로 읽어 한 번에 약 5분 걸립니다. 실패한 계정 몇 개는 다음 실행 때 다시 읽습니다.
  처음엔 부스원 계정까지 봤지만(계정 164개, 2026-10-04 시험 후보 47개) 사용자 요청으로 부스장만 보도록 줄였습니다.
- **관리 화면**: `admin.html` (사이트와 별도 파일, 한국어만, 검색엔진 제외)
  - 후보: `https://raw.githubusercontent.com/mononono97/FurryBoothList/x-post-feed/candidates.json`
  - 결정: Firestore `boothPosts/main` 문서
    - `approved`: `{ 글id: { booth: "A02", handle, at, text, sensitive, quote, images } }`. `text`·`sensitive`·`quote`·`images`(민감한 글은 빈 목록)는 반영할 때
      `fetchPostInfo()`가 FxTwitter(`/2/status/<id>`)에서 받아 저장(실패하면 후보 파일 값)
    - `excluded`: `{ 글id: true }`
  - 함수: `approve()`, `exclude()`, `undo()` (모두 `set(..., { merge: true })`), 직접 추가 `parseStatusUrl()`, 부스 자동 선택 `boothsForHandle()`
- **사이트 표시**: `index.html`
  - `loadApprovedBoothPosts()`: 첫 부스 상세 창을 열 때 `boothPosts/main`을 한 번 읽고, 오프라인 대비로 localStorage `furstclass-booth-posts`에 저장
  - `buildBoothPosts(booth, onShown)`: 부스컷 자리(제목 바로 아래)에 반영된 글을 최신순으로 `createTweet` 임베드. 반영된 글이 없으면 아무것도 보이지 않음.
    글이 있으면 `onShown`으로 `openBoothModal()`이 부스컷(`buildBoothCut()`)을 지움. 첫 Firestore 읽기 동안은 부스컷이 잠깐 보였다가 바뀔 수 있음
    `sensitive`이거나 `quote`인 글, 그리고 12초 안에 임베드가 안 되는 글(X 스크립트 차단, 나중에 민감한 글로 바뀐 글 등)은 `buildBoothPostCard()` 카드로 보여줌. 카드 본문 끝의 t.co 링크는 `cardText()`가 지움
  - 번역 키: `boothPostOpenX`, `boothPostSensitive`
  - 번역 키: `boothPostsTitle` (상품 정보 / Merch info / 頒布物情報)
  - **최근 갱신 탭**: `currentRow === "UPDATES"`. `recentlyUpdatedBooths()`가 반영된 글을 부스별로 묶어 가장 최근 글 시각(`postTime()`, 글 id에서 계산한 X 작성 시각) 내림차순으로 정렬.
    날짜는 반영한 날이 아니라 작가가 글을 올린 날 기준. 우선순위 정렬 버튼은 숨김. 번역 키 `updatesBtn`, `updatesCount`, `emptyUpdates`, `updatedOn`
- **Firestore 규칙** (Firebase 콘솔에서 운영자가 한 번 추가, 관리 화면의 "반영 권한 설정 방법"에서 UID가 채워진 규칙을 복사할 수 있음):
  ```
  match /boothPosts/{doc} {
    allow read: if doc == "main" || isBoothPostsAdmin();
    allow write: if isBoothPostsAdmin();
  }
  function isBoothPostsAdmin() {
    return request.auth != null && request.auth.uid == "<운영자 UID>";
  }
  ```

## 확인 방법
1. GitHub 저장소 → Actions → "부스 상품 글 후보 모으기" → Run workflow → 끝나면 로그에 "새 후보 N개"와 후보 목록이 보이는지 확인
2. 사이트 주소 뒤에 `/admin.html`을 붙여 열고 Google 로그인 → 위에 UID가 보이는지 확인
3. (처음 한 번) "반영 권한 설정 방법"의 규칙을 복사해 Firebase 콘솔 → Firestore Database → 규칙에 추가하고 게시
4. 대기 탭의 후보 하나에서 "반영" → 반영됨 탭으로 옮겨지는지 확인
5. 사이트에서 그 부스 상세 창을 열어 "상품 정보" 아래에 그 X 글이 보이는지 확인
6. 반영됨 탭에서 "대기로 되돌리기" → 사이트를 새로고침하면 부스 상세 창에서 사라지는지 확인
7. 로그아웃하거나 다른 계정으로 로그인하면 목록 대신 "관리 권한이 없습니다"가 나오는지 확인
8. "민감한 글" 표시가 붙은 후보(예: B-11)에서 "사이트에 보일 모양"을 누르면 본문 카드가 나오는지, 반영 후 사이트 부스 상세에도 카드로 보이는지 확인
