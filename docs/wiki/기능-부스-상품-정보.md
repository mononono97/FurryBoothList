# 부스 상품 정보 (X 글 후보 수집과 관리 화면)

관리 화면은 행사 안내 탭에 보일 **공식 계정 글**도 같은 방식으로 고릅니다(2026-10-05부터, 아래 "행사 안내 글").

## 무엇을 하나
- 부스장·부스원 X 계정이 올린 글 중 **상품 글 같아 보이는 글**을 1시간마다 자동으로 모아 후보로 쌓습니다(부스원 계정은 2026-10-24부터 다시 포함).
- **RT 계정(2026-10-24)**: 운영 쪽 리트윗 전용 계정 **@furstclassrt**가 리트윗한 글은 키워드 판단 없이 모두 부스 상품 글 후보에 들어옵니다. 후보에 **"RT 계정"** 표시가 붙습니다.
  - 글쓴이가 부스장이면 그 부스, 부스원이면 그 부스원이 속한 부스로 자동 지정됩니다(두 부스에 있으면 반영할 때 고름).
  - 부스 명단에 없는 사람의 글이면 **"부스 미지정"**으로 들어오고, 반영 버튼 옆 목록에서 부스를 골라야 반영됩니다.
  - 이미 키워드로 후보에 들어와 있던 글을 리트윗하면 그 후보에 "RT 계정" 표시만 덧붙습니다.
  - @furstclassrt가 직접 쓴 글(공지·인용 글)은 넣지 않습니다. 반영 전에 운영자가 한 번 더 확인하는 흐름은 그대로입니다.
  - **2026-09-01(한국 시간) 이전에 쓴 글은 리트윗해도 후보에 넣지 않습니다**(2026-10-25). 이전 행사 글이라서입니다. 이미 대기 목록에 쌓여 있던 3~4월 글 126개(+ 제외해 둔 4개)도 다음 수집 때 후보 파일에서 지웁니다. 이미 반영된 글은 Firestore에 따로 있어 영향이 없습니다(지우는 글 중 반영된 글은 0개였음).
- 운영자는 관리 화면(`admin.html`, 사이트 주소 뒤에 `/admin.html`)에서 후보를 보고 **반영** 또는 **제외**를 누릅니다.
- 반영한 글은 사이트의 부스 상세 창에 **"상품 정보"** 제목 아래 X 글 모양으로 바로 나타납니다. 다시 배포할 필요가 없습니다.
- 반영된 글이 있는 부스는 상세 창 맨 위의 **부스컷 대신** 상품 정보 글이 보입니다. 반영된 글이 없는 부스는 지금처럼 부스컷이 보입니다.
- **글 목록 스크롤(2026-10-24)**: 상품 정보 글은 정해진 높이 안에서 따로 스크롤됩니다. PC 펼침 상세는 화면 높이에 맞춰(900px 높이 화면에서 약 500px, 최소 320px), 휴대폰·모달은 화면 높이의 60%(최대 640px)까지입니다.
  글이 그 높이보다 짧으면(보통 글 1개) 스크롤바도 빈 공간도 없이 원래 높이 그대로 보입니다. 아래에 글이 더 남아 있으면 목록 끝이 흐려지고, 글이 2개 이상이면 제목에 "상품 정보 (3)"처럼 글 수가 붙습니다.
- **상품 정보 글 숨기기(2026-10-26 사용자 요청)**: 방문자는 부스 상세의 상품 정보 글마다 위에 있는 **"숨기기"** 버튼으로 보기 싫은 글을 숨길 수 있습니다.
  - 숨긴 글이 있으면 "상품 정보" 제목 오른쪽에 **"모두 보기 (숨긴 글 N개)"** 버튼이 생깁니다. 누르면 숨긴 글까지 전부 보이고, 숨긴 글은 흐리게 "숨긴 글" 표시와 함께 나옵니다.
  - 그 화면에서 숨긴 글의 **"다시 보이기"**를 누르면 복구됩니다. 버튼은 "숨긴 글 감추기"로 바뀌어 다시 접을 수 있고, 숨긴 글을 모두 복구하면 버튼이 사라집니다.
  - 제목의 글 수 "(N)"는 지금 보이는 글 수입니다. 한 부스의 글을 모두 숨기면 "이 부스의 상품 정보 글을 모두 숨겼어요."가 보입니다(부스컷이 다시 나오지는 않음).
  - 숨김은 글 단위로 이 기기(localStorage)에 저장되고, Google 로그인 중이면 메모·방문 상태처럼 로그인할 때와 "지금 동기화"를 누를 때 다른 기기와 맞춰집니다. 설정의 "데이터 초기화"를 하면 숨김도 모두 풀립니다.
  - 운영자 쪽(관리 화면 반영·제외)에는 영향이 없고, 다른 방문자에게도 그대로 보입니다. 최근 갱신 탭에도 그대로 나옵니다.
- 후보에 없는 글(키워드가 없는 상품 글 등)은 관리 화면의 **"글 주소로 직접 추가"** 칸에 X 글 주소를 붙여 넣어 반영할 수 있습니다.
- 반영됨·제외됨 탭에서 **"대기로 되돌리기"**를 누르면 결정을 취소합니다.
- 부스 상품 글의 **반영됨 탭**은 글을 한 줄로 늘어놓지 않고, 반영된 글이 있는 부스만 사이트 부스 목록처럼 **부스 카드**(부스컷·부스 번호·이름·대표, 오른쪽 위 초록 숫자 = 반영된 글 수, 아래 "10/7 갱신" = 그 부스의 가장 최근 글 작성 날짜)로 보여줍니다.
  정렬은 **가장 최근 글이 올라온 부스부터**입니다(사이트 "최근 갱신" 탭과 같은 기준, 2026-10-08 사용자 요청).
  카드를 누르면 그 부스에 반영된 글만 최신순으로 펼쳐지고, "← 부스 목록"으로 돌아옵니다(2026-10-08 사용자 요청). 행사 안내 글의 반영됨 탭은 예전처럼 글 목록입니다.
- 관리 화면은 운영자 계정으로 로그인해야 목록이 보입니다. 로그인하지 않았거나 다른 계정이면 "관리 권한이 없습니다"만 보입니다.
- X가 **민감한 내용**으로 표시한 글은 X가 임베드를 막아("Not found") 사이트에서 **아이디·작성 날짜와 "X에서 보기" 링크만 있는 카드**로 보입니다(본문·이미지 없음). 작성 날짜는 글 id에서 계산하므로 따로 저장하지 않습니다.
  관리 화면 후보에는 "민감한 글" 표시와 같은 안내가 붙습니다.
- 민감한 글로 표시되지 않았어도 X 임베드가 **오류로 끝나거나 내용 없이 빈 칸으로 남으면**(나중에 민감한 글로 바뀐 글, 지워졌거나 비공개가 된 글 등) 같은 링크 카드로 바뀝니다(2026-10-24, B-08 글이 빈 칸으로 보이던 문제).
  2026-10-27부터는 **"Not found"만 보이는 칸**도 같은 링크 카드로 바뀌고, 임베드가 끝나지 않는 글은 8초(전에는 12초) 뒤에 바뀝니다(C-14 @HOKIpong 글이 "Not found"로 보이던 문제).
- 관리 화면 **반영됨 탭**의 부스 상품 글에는 **"링크 카드로 보이기"** 버튼이 있습니다(2026-10-27). 민감한 글로 표시되지 않아 임베드를 시도했는데 X가 "Not found"를 보여주는 글은
  이 버튼을 누르면 사이트에서 처음부터 링크 카드로 보입니다(방문자에게는 최대 10분 뒤 반영). 누른 글에는 "민감한 글 · 링크 카드" 표시가 붙고, **"임베드로 되돌리기"**로 원래대로 돌립니다.
- 다른 글을 **인용한 글**도 다른 글처럼 X 공식 임베드로 보입니다(인용된 글도 함께 보임).
- 관리 화면의 후보는 본문 대신 **X 공식 임베드**로 보여줍니다. 화면에 가까워진 후보부터 차례로 불러옵니다.
- **행사 안내 글**: 관리 화면 위쪽의 "행사 안내 글"을 누르면 공식 계정(@FURSTCLASS_KR)의 새 글 후보가 같은 대기·반영됨·제외됨 탭으로 보입니다.
  반영한 글만 사이트의 행사 안내 탭에 최신순으로 나옵니다. "대기 글 모두 반영"으로 한 번에 반영할 수 있고, "글 주소로 직접 추가"에 공식 글 주소를 넣어도 됩니다.
  하나도 반영하지 않았으면 미리 정해 둔 최근 글 6개가 나옵니다.
- 위쪽 탭의 **🆕 최근 갱신** 탭은 반영된 상품 정보 글이 있는 부스만, 가장 최근 글이 올라온 부스부터 보여줍니다. 카드 아래에 "10/4 갱신"처럼 그 글을 올린 날짜가 붙습니다.
  - **⭐ 내 부스만(2026-10-18)**: 탭 위의 "전체 / ⭐ 내 부스만" 버튼. 내 부스만은 메모·방문 상태·우선순위·예산·쓴 돈·선입금 중 하나라도 적어 둔 부스만 남깁니다. 고른 버튼은 새로고침해도 유지됩니다.
  - **NEW 표시(2026-10-18)**: 마지막으로 이 탭을 본 뒤 새 글이 올라온 부스는 날짜 앞에 빨간 **NEW**가 붙고, 다른 탭에 있을 때 탭 버튼 "🆕 최근 갱신" 옆에 빨간 점이 뜹니다. 탭을 열면 그때까지의 글을 본 것으로 기억하고(탭을 보는 동안에는 NEW가 그대로), 다음에 다시 열 때 사라집니다. 이 탭을 한 번도 열지 않은 사람은 NEW·점 없이 시작합니다.

## 왜 이렇게 했나
- **내 부스만·NEW를 넣은 이유(2026-10-18 사용자 요청)**: 행사 직전에 부스들이 신간·품절·추가 굿즈 공지를 몰아서 올리므로, 내가 가려는 부스의 새 소식만 빨리 확인할 수 있게 했습니다.
  NEW 기준은 서버가 아니라 이 기기(localStorage)에만 저장해서 Firestore 읽기·쓰기가 늘지 않습니다. 다만 탭 버튼의 점을 띄우려고, 이 탭을 본 적이 있는 사람은 페이지를 연 3초 뒤 상품 글 목록을 받아 둡니다(10분 캐시라 Firestore 읽기는 10분에 한 번 이하, 예전에도 부스 상세를 처음 열 때 한 번 읽었음).
- **RT 계정 글을 키워드 없이 받는 이유(2026-10-24 사용자 요청)**: 운영자가 직접 골라 리트윗한 글이라 키워드로 다시 거를 필요가 없고, 키워드가 없는 상품 글도 리트윗만 하면 후보에 올릴 수 있게 하려는 것입니다.
  자동 반영 대신 후보로만 넣은 이유는 잘못 리트윗한 글이 바로 사이트에 나가지 않게 하고, 부스 명단에 없는 사람의 글은 어느 부스인지 사람이 골라야 하기 때문입니다.
- **부스원 계정을 다시 넣은 이유(2026-10-24 사용자 요청)**: 부스장만 보니 부스원이 올린 상품 글이 많이 빠졌습니다. 후보가 늘어나는 대신 운영자가 대기 탭에서 제외하면 됩니다.
- 작가들에게 해시태그를 정해서 올려 달라고 하기 어렵다는 사용자 의견(2026-10-04)에 따라, 평소 글에서 자동으로 골라내고
  사람이 마지막에 확인하는 방식으로 정했습니다.
- **글 목록을 스크롤로 바꾼 이유(2026-10-24 사용자 요청)**: X 임베드는 사진이 있으면 글 하나가 500~700px이라, 글이 여러 개인 부스는 상세 창이 너무 길어져 아래의 방문 표시·예산·메모까지 한참 내려가야 했습니다.
  `height`가 아니라 `max-height`를 써서 글이 적은 부스는 예전과 똑같이 보이게 했습니다.
- **판단 방식**: 사용자 결정(2026-10-04)으로 무료인 키워드 점수로 시작하고, 정확도가 아쉬우면 나중에 AI(Claude API) 판단을 붙입니다.
  어차피 운영자가 최종 확인하므로 조금 넓게 잡아도 괜찮습니다.
- **X 공식 API를 쓰지 않은 이유**: 글 읽기가 유료입니다. 대신 행사 안내 탭에서 이미 쓰는 FxTwitter 공개 JSON(무료·키 없음)을 씁니다.
- **방문자 브라우저가 아니라 GitHub Actions가 모으는 이유**: 부스장 계정이 약 100개라 방문자마다 조회하면 느리고 FxTwitter 제한에 걸리기 쉽습니다.
  클라우드 개발 환경에서는 FxTwitter가 막혀 있지만 GitHub Actions에서는 열려 있음을 2026-10-04에 확인했습니다.
- **후보를 main이 아니라 `x-post-feed` 브랜치에 쌓는 이유**: main에 커밋할 때마다 Cloudflare가 사이트를 다시 배포하기 때문입니다.
- **반영 목록을 Firestore에 두는 이유**: 관리 화면에서 누르는 즉시 사이트에 반영되고, GitHub 토큰 같은 비밀값 없이
  이미 쓰고 있는 Google 로그인만으로 운영자를 구분할 수 있습니다.
- **운영자 UID를 코드에 넣지 않은 이유**: 공개 저장소라서입니다. 관리 화면은 운영자만 읽을 수 있게 규칙을 건
  `boothPosts/admin` 문서를 읽어 보고, 권한 오류가 나면 목록을 숨깁니다(사용자 요청, 2026-10-04).
  후보 파일 자체는 GitHub 공개 저장소에 있으므로 완전히 숨기는 것은 아닙니다. 보이는 내용은 원래 X에 공개된 글입니다.
- **민감한 글을 카드로 보여주는 이유**: X 임베드는 민감한 글(`possibly_sensitive`)에 대해 `TweetTombstone`을 돌려줘
  "Not found"만 보이고 `createTweet()`도 끝나지 않습니다(2026-10-04 GitHub Actions 브라우저로 확인, B-11·B-02 글).
  이미지는 민감한 내용일 수 있어 사이트에 넣지 않고 X 링크로 보냅니다.
- **글 본문·이미지를 저장하지도 직접 그리지도 않는 이유 (2026-10-05)**: X 개발자 약관은 X 콘텐츠를 공식 방식(임베드 등)으로 작성자·시각·X 로고와 함께 보여주고,
  원글이 지워지거나 비공개가 되면 사본도 지우도록 요구합니다. 본문·이미지 사본을 공개 저장소(`x-post-feed`)와 Firestore에 두고 직접 카드로 그리던 방식,
  특히 X가 일부러 임베드를 막은 민감한 글의 본문을 보여주던 방식이 여기에 어긋날 수 있다는 검토 결과에 따라 사용자가 바꾸기로 했습니다.
  그래서 인용 글을 숨기려고 직접 그리던 카드(2026-10-04, #35)도 없애고 공식 임베드로 되돌렸습니다. X 임베드에는 인용 글을 숨기는 옵션이 없습니다.
  (법률 자문이 아니라 약관을 읽고 정한 방향입니다.)
- **후보 수집은 계속 FxTwitter를 쓰는 이유**: X 공식 API는 유료이고, 후보 수집은 방문자에게 보이지 않는 운영자 도구라 위험이 작다고 보고 그대로 두었습니다(사용자 결정, 2026-10-05).
  방문자 브라우저가 FxTwitter를 부르던 곳(행사 안내 탭)은 없앴습니다.

   (사이트는 10분에 한 번만 새로 읽으므로, 바로 보려면 10분 기다리거나 F12 → Application → Local storage에서 `furstclass-booth-posts-fetched-at`을 지우고 새로고침. 5·11번도 같음)

    카드를 누르면 그 부스 글만 보이는지, "← 부스 목록"으로 돌아오는지, 글이 하나뿐인 부스에서 "대기로 되돌리기"를 누르면 부스 목록으로 돌아오고 카드가 사라지는지 확인

    관리 화면 대기 탭에서 그 글에 "RT 계정" 표시와 부스 번호(명단에 없는 사람이면 "부스 미지정"과 부스 선택 목록)가 보이는지, 반영하면 그 부스 상세 창에 보이는지 확인

    글이 1개인 부스는 스크롤바·빈 공간 없이 예전처럼 보이는지, 다크 모드에서도 같은지 확인
17. (9월 이전 글 정리) 병합 후 Actions에서 Run workflow → 로그에 "2026-09-01(KST) 이전 글 후보 130개 정리"가 나오는지 확인 →
    관리 화면 대기 탭에 2026년 3~4월 글이 더 이상 없고, 반영됨 탭의 부스 카드·글 수는 그대로인지 확인
18. (숨기기) 상품 정보 글이 여러 개인 부스 상세를 열고 글 하나의 "숨기기" → 그 글이 사라지고 제목 옆에 "모두 보기 (숨긴 글 1개)"가 생기는지, 제목의 글 수가 하나 줄었는지 확인 →
    "모두 보기"를 누르면 숨긴 글이 흐리게 "숨긴 글" 표시와 함께 보이는지 → "다시 보이기"를 누르면 흐림이 풀리고, 숨긴 글이 없어지면 버튼이 사라지는지 확인.
    새로고침해도 숨김이 유지되는지, 글을 모두 숨기면 "모두 숨겼어요" 안내가 보이는지, PC 펼침 상세·휴대폰 창, 라이트·다크 모드에서 모두 확인.
19. ("Not found" 글, 2026-10-27) 병합·배포 후 사이트에서 C-14 부스 상세를 열고 10초쯤 기다려 "Not found" 대신 "@HOKIpong · 날짜"와 "X에서 보기" 링크 카드로 바뀌는지 확인.
    그래도 "Not found"가 남으면 관리 화면 → 반영됨 탭 → C14 카드 → 그 글의 "링크 카드로 보이기" → 사이트의 `furstclass-booth-posts-fetched-at`을 지우고 새로고침하면 처음부터 링크 카드로 보이는지 확인.
    "임베드로 되돌리기"를 누르면 다시 임베드를 시도하는지, 정상 글이 많은 부스(예: A03)의 임베드는 그대로 보이는지도 확인
    로그인한 두 기기에서 한쪽에서 숨기고 "지금 동기화" → 다른 쪽에서 "지금 동기화" 후 부스 상세를 다시 열면 숨겨져 있는지, 복구도 같은 방법으로 전해지는지 확인
