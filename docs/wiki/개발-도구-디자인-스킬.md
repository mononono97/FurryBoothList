# 개발 도구: 디자인 스킬 3개

## 무엇을 하나
저장소의 `.claude/skills/` 폴더에 Claude Code 디자인 스킬 3개를 넣어 두었습니다.
이 저장소로 작업하는 Claude(프로젝트 스레드, PC의 Claude Code)는 따로 설치하지 않아도 이 스킬을 씁니다.
사이트 화면이나 동작은 바뀌지 않습니다.

| 스킬 | 하는 일 |
|---|---|
| `hallmark` | 새 페이지를 "AI가 만든 티 안 나게" 디자인. 기존 화면에는 `/hallmark redesign <경로>`, `/hallmark audit <경로>`처럼 이름을 불러야만 씀 |
| `design-taste-frontend` (taste-skill) | 랜딩·회사 사이트 같은 페이지를 만들거나 다듬을 때 쓰는 디자인 규칙과 부품, 브라우저 검사기 |
| `impeccable` | 기존 화면의 디자인 평가(critique/audit), 다듬기(polish), 애니메이션 등 명령형 디자인 작업 |

출처 저장소, 가져온 커밋 해시, 라이선스, 넣지 않은 파일은 `.claude/skills/README.md`에 있습니다.

## 왜 이렇게 했나
- 사용자 요청(2026-11-22): 스레드에서도 디자인 스킬을 쓰고 싶음. 스레드는 매번 저장소를 새로 받으므로
  전역 설치(`~/.claude/skills`)로는 남지 않고, 저장소 안 `.claude/skills/`에 두어야 매번 쓸 수 있습니다.
- 전역 설치기, 설정 파일에 훅을 써 넣는 설치기, 다른 에이전트용 메타데이터는 저장소에 둘 이유가 없어 뺐습니다.
- 가져온 스크립트는 넣기 전에 훑어봤습니다(자격 증명 읽기, 외부로 데이터 보내기, 임의 코드 실행 없음).
  외부 접속은 사진·아이콘 내려받기, 지도 데이터 조회, impeccable 엔진 바이너리 내려받기(sha256 확인),
  `TOGETHER_API_KEY`가 있을 때만 이미지 생성 정도입니다.

## 어떻게 구현했나
- 파일 위치: `.claude/skills/hallmark/`, `.claude/skills/design-taste-frontend/`, `.claude/skills/impeccable/`
  (약 50MB, 대부분 taste-skill의 예시 사진·부품)
- 배포 제외: `.assetsignore`에 `.claude` 한 줄 추가. Cloudflare 정적 배포에 올라가지 않습니다.
- `design-taste-frontend`는 스킬 사용 중 턴이 끝날 때 `scripts/gate.mjs`를 실행하는 Stop 훅을 갖고 있습니다.

### 실행 환경별로 되는 것
| 환경 | 상태 |
|---|---|
| 프로젝트 스레드(클라우드) | Node 22와 Chrome(`/usr/bin/google-chrome`), Playwright Chromium이 있음. taste-skill 검사기는 npm 패키지 없이 Node + Chrome만 씀. hallmark의 정적 검사(`sloplint.mjs`)는 Node만으로 되고, 화면을 띄우는 `--render` 검사는 `puppeteer-core`가 필요(세션마다 `npm i -g puppeteer-core`, npm 접속 가능). impeccable은 처음 실행 때 GitHub에서 엔진을 받음(GitHub 접속 가능) |
| PC의 Claude Code | Node와 Chrome이 설치돼 있으면 같은 방식으로 동작 |

## 확인 방법
1. PR을 병합한 뒤 이 저장소로 새 스레드나 Claude Code를 열고 `/hallmark`, `/impeccable`, `/design-taste-frontend` 중 하나를 입력해 스킬 목록에 뜨는지 봅니다.
2. 배포 후 `https://furryboothlist.hwch.workers.dev/.claude/skills/README.md`를 열어 404가 나오면 배포에서 빠진 것입니다.
3. 사이트(부스 목록, 우선순위 정렬, 로그인 동기화, 메모·방문 상태·예산)는 파일을 건드리지 않았으므로 그대로입니다.
