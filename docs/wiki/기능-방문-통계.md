# 방문 통계 (Cloudflare Web Analytics)

## 무엇을 하나
- 방문자에게 보이는 변화는 없습니다. 운영자가 Cloudflare 대시보드에서 일별 방문자 수·페이지뷰·국가·기기·유입 경로를 볼 수 있게 합니다.
- 보는 곳: Cloudflare 대시보드 → Analytics & Logs → **Web Analytics** → `furryboothlist.hwch.workers.dev`
- 켠 날(2026-10-31, main 배포 시점)부터만 집계됩니다. 그 전 기록은 없습니다.

## 왜 이렇게 했나
- 2026-10-31 사용량을 확인하려 했을 때 사이트에는 방문 통계 코드가 없었습니다.
  - firebaseConfig에 `measurementId`(Google Analytics)가 있지만 Analytics SDK는 불러오지 않아 GA에는 데이터가 없습니다.
  - 서버 코드 없는 정적 배포라 서버 로그도 없습니다.
  - 그때 볼 수 있던 숫자: Cloudflare 계정 대시보드의 요청·Visits(지난 7일 약 1,030 Visits), Firebase Authentication의 로그인 사용자 수(10월 38명). 로그인은 선택 기능이라 실제 이용자보다 훨씬 적습니다.
- Cloudflare Web Analytics를 고른 이유: 무료, 쿠키를 쓰지 않음(동의 창 불필요), 이미 쓰는 Cloudflare 계정에서 바로 볼 수 있음.
  Google Analytics(Firebase Analytics)는 쿠키를 쓰고 SDK가 커서 버렸습니다.
- 사이트 주소가 Cloudflare에 등록한 도메인이 아닌 `workers.dev`라서 자동 연결이 안 되고
  ("This hostname does not belong to any website on your Cloudflare account"), JS 스니펫을 직접 넣는 방식입니다.
- 관리 화면(`admin.html`)은 운영자만 쓰므로 넣지 않았습니다(통계에 섞이지 않게).

## 어떻게 구현했나
- `index.html` 맨 끝 `</body>` 바로 앞에 `static.cloudflareinsights.com/beacon.min.js` 스크립트 한 줄(`defer`, `data-cf-beacon`의 token).
  토큰은 원래 페이지에 공개되는 값입니다.
- `index.html` 상단 Content-Security-Policy:
  - `script-src`에 `https://static.cloudflareinsights.com`
  - `connect-src`에 `https://cloudflareinsights.com` (집계 데이터 전송)
- `defer`라서 부스 목록 그리기를 늦추지 않고, 차단되거나 오프라인이어도 사이트 동작에는 영향이 없습니다.
- 서비스 워커(`sw.js`)는 다른 도메인 요청을 건드리지 않으므로 수정하지 않았습니다.
- 광고 차단기를 쓰는 방문자는 집계되지 않을 수 있어서 실제보다 조금 적게 나올 수 있습니다.

## 확인 방법
1. 배포 후 사이트를 열고 개발자 도구(F12) → 네트워크에서 `beacon.min.js`가 200으로 받아지고,
   `cloudflareinsights.com/cdn-cgi/rum` 요청이 나가는지 확인합니다.
2. 콘솔에 "Content Security Policy" 오류가 없어야 합니다.
3. 몇 분~몇 시간 뒤 Cloudflare 대시보드 → Web Analytics에서 방문이 잡히는지 확인합니다.
