# 사이트 구조

빌드 과정이 없는 정적 사이트입니다. 파일을 그대로 올리면 동작합니다.
(부스 데이터만 파이썬 스크립트로 `index.html` 안에 생성해 넣습니다.)

## 파일 구성
| 경로 | 역할 |
|---|---|
| `index.html` | 사이트 전체 (HTML + CSS + JS, 부스 데이터 포함) |
| `sw.js` | 오프라인 열람용 서비스 워커 (캐시 이름 `furstclass-cache-v1`) |
| `avatars/` | 부스원 X 프로필 사진. 파일명은 `<X 아이디>.jpg` (대소문자까지 정확히) |
| `booth-cuts/` | 부스컷 이미지. 파일명은 `<부스 번호>.jpg` (예: `A01.jpg`, 두 칸 부스는 `A37-38.jpg`). 규칙은 `booth-cuts/README.md` |
| `data/furstclass_booths.csv` | 행사 측이 준 부스 시트 원본(CSV) |
| `data/x-handles-missing-avatars.txt` | 프로필 사진이 아직 없는 X 아이디 목록 (스크립트가 갱신) |
| `tools/build_booths.py` | 시트 CSV → `index.html`의 `BOOTHS` 생성 |
| `tools/fetch_avatars.py` | 사진 없는 부스원의 X 프로필 사진을 받아 `avatars/`에 저장 (PC에서 실행) |
| `docs/wiki/` | 이 위키 |
| `favicon.png` | 파비콘 |

## 부스 데이터
`index.html` 안의 `BOOTHS` 배열입니다. 직접 고치지 말고 시트 CSV를 바꾼 뒤 `python3 tools/build_booths.py`로 다시 만듭니다.

```js
{ id: "A10", block: "A", num: "10", nums: ["10"], adult: false, name, rep, twitter, cut: true,
  members: [{ name, twitter, role: "leader" | "member" }] }
```
- 열은 A(일반), B·C(성인) 세 개입니다. 두 칸 부스는 `id: "A37-38"`, `nums: ["37","38"]`처럼 한 부스로 합칩니다.
- 시트 열 구성, 이름/X 아이디 파싱 규칙, 예외 처리(`OVERRIDES`, `HANDLE_FILL`, `SAME_AS_LEADER`)는
  [부스원과 부스컷](기능-부스원과-부스컷.md)에 정리되어 있습니다.
- 배포 환경(Cloudflare)은 파일명 대소문자를 구분하므로 X 아이디와 사진 파일명이 정확히 같아야 합니다.

## 저장 방식 (localStorage 키)
모든 키는 `STORAGE_PREFIX = "furstclass"`로 시작합니다.

| 키 | 내용 |
|---|---|
| `furstclass-notes` | 부스별 메모 `{ "A10": "..." }` |
| `furstclass-visit-status` | 방문 예정/완료 |
| `furstclass-budget` | 부스별 예산(원) |
| `furstclass-priority` | 부스별 우선순위 1~3 |
| `furstclass-sort-priority` | 우선순위 정렬 켜짐 여부 |
| `furstclass-current-row` | 마지막으로 보던 탭 |
| `furstclass-lang` | 선택 언어 |

- 지난 행사의 `kemoket-*` 키는 접속할 때 지웁니다.
- 로그인하면 메모·방문 상태·예산·우선순위가 Firestore `users/<uid>` 문서의 `furstclass` 필드에도 저장됩니다.
  자세한 내용은 [Google 로그인과 동기화](기능-Google-로그인-동기화.md).

## 외부 서비스
- Firebase Authentication(Google) + Firestore: 로그인·동기화 (프로젝트 `boothlist-4589c`)
- Open-Meteo: 행사 당일 날씨 (API 키 불필요)
- Google Maps 임베드: 약도
- `index.html` 상단의 Content-Security-Policy에 허용 도메인이 정리되어 있으므로,
  새 외부 서비스를 붙일 때는 여기도 함께 고쳐야 합니다.

## 배포
Cloudflare Workers(서비스 이름 `furryboothlist`, 예전 이름 `kemoket-list`)에서 정적 호스팅합니다.
main 브랜치에 반영되면 배포됩니다.

- main이 아닌 브랜치의 빌드(미리보기)는 2026-10-02에 껐습니다. 켜져 있을 때는 내용과 상관없이
  브랜치 빌드가 항상 실패해서 PR에 빨간 체크가 떴기 때문입니다. 그래서 PR에는 배포 체크가 없고,
  main에 머지된 뒤의 배포 결과만 확인하면 됩니다.

## 브랜치
- `main`: 배포되는 사이트 (지금은 Furst Class)
- `kemoket`: 케모켓(2026-09-20 도쿄) 사이트의 마지막 상태(커밋 `137e0ae`) 보관용
