# 메모·방문 상태·예산

## 무엇을 하나
- 부스마다 개인 메모를 남길 수 있습니다(최대 1000자, 예시 문구 "동인지 한권, 아크릴 키링 하나"). 저장 버튼 없이 입력하는 즉시 저장되고 오른쪽 아래에 "저장됨"이 잠깐 보입니다. "삭제" 버튼은 메모를 비웁니다.
- 방문 예정(노란색) / 방문 완료(초록색)를 토글할 수 있고, 부스 카드와 배치도에 색으로 표시됩니다.
- 상태 없이 메모만 있는 부스는 클레이(주황)색으로 구분합니다.
- 부스별 예산(Furst Class부터 원 단위, 1,000원 단위 입력. 케모켓 때는 엔)을 입력하면 메모 탭에서 총합이 보입니다.
- 부스별 **쓴 돈**(원): 예산 칸 오른쪽에 "쓴 돈 (원)" 칸이 있어 행사장에서 실제로 쓴 금액을 적습니다(2026-10-18).
  - 메모 탭 위 합계가 "예산 ₩65,000 · 쓴 돈 ₩40,000 · 남은 예산 ₩25,000"처럼 바뀌고, 예산을 넘으면 "₩5,000 초과"로 빨갛게 보입니다. 쓴 돈을 하나도 안 적었으면 예전처럼 "총 예산"만 보입니다.
  - 메모 탭 카드 아래에 "💸 ₩40,000 / 예산 ₩15,000"(쓴 돈이 있을 때) 또는 "예산 ₩30,000"이 붙습니다. 예산을 넘은 부스는 빨간 글씨입니다.
  - 선입금 금액은 선입금 탭 합계에 따로 있어 여기에는 더하지 않습니다.
- 메모 탭: 메모·상태·예산·쓴 돈이 있는 부스만 모아 보고, 전체/방문 예정/방문 완료/**🧭 동선 보기**로 필터링합니다. 고른 필터는 새로고침해도 유지됩니다(2026-10-18~).
  - **🧭 동선 보기**: 방문 예정·방문 완료 부스만, A구역 · 그랜드볼룸 / B구역 · 그랜드볼룸 / C구역 · 주성홀 머리줄로 묶어 보여줍니다. 구역 안에서는 아직 안 간 부스를 번호 순(우선순위순 정렬을 켜면 우선순위 순)으로 먼저, 다녀온 부스는 뒤로 보냅니다.
    위쪽에 "방문 완료 2 / 6곳 · 남은 곳 4", 머리줄마다 "남은 곳 1 / 4"(다 다녀오면 "✅ 4곳 모두 다녀옴")가 보입니다.
  - 메모 탭 카드 중 방문 예정·완료 부스에는 카드 아래 **"✓ 방문 완료"** 버튼(이미 다녀온 부스는 "↩ 되돌리기")이 있어, 상세 창을 열지 않고 바로 방문 완료로 바꿉니다. 모든 메모 탭 필터에서 보입니다.

## 왜 이렇게 했나
- 행사장에서 동선을 짜고 지출을 관리하려는 용도입니다.
- 메모만 있는 부스가 방문 예정과 같은 노란색 계열이라 헷갈려서 색을 따로 분리했습니다.
- **동선 보기·바로 완료 버튼(2026-10-18 사용자 요청)**: 행사장에서는 걸어가는 구역 순서대로 보는 게 편하고, 사고 나서 상세 창을 열어 "방문 완료"를 누르는 단계가 번거롭습니다. 구역은 홀이 다른 C구역(주성홀)이 따로 묶이도록 A→B→C 순서로 둡니다.
  "✓ 방문 완료"를 누르면 방문 예정 → 방문 완료, 다시 누르면 방문 예정으로 돌아갑니다(상태를 지우지는 않아 동선 목록에서 빠지지 않음).
- **쓴 돈을 예산과 따로 둔 이유(2026-10-18 사용자 요청)**: 예산은 계획이라 당일 "얼마 남았지?"를 알 수 없었습니다. 예산 칸을 쓴 돈으로 덮어쓰면 계획이 사라지므로 칸을 나눴습니다.
- 메모만 저장 버튼을 눌러야 해서, 휴대폰에서 메모를 쓰고 창 바깥을 눌러 닫으면 그대로 사라졌습니다. 예산·선입금 칸처럼 즉시 저장으로 맞췄습니다(2026-10-08 사용자 요청).
- 데이터는 기본적으로 브라우저에만 저장됩니다. 기기 간에 옮기려면 처음엔 JSON
  내보내기/가져오기를 썼고, 지금은 [Google 로그인 동기화](기능-Google-로그인-동기화.md)로 대체했습니다.

## 어떻게 구현했나
- 키 이름은 `STORAGE_PREFIX`("furstclass")로 만들어짐 (`furstclass-notes` 등)
- 메모: `NOTES_KEY`, `loadNotes/saveNotes/getNote/setNote`, `updateNoteVisuals()`, `MAX_NOTE_LENGTH`
- 메모 즉시 저장(`fillBoothActions()`의 textarea `input`): 글자마다 `setNote()` + 카드 메모 표시, 탭 버튼 개수·배치도 색은 입력이 0.4초 멈추면 갱신. 메모 탭 목록은 입력 중에 다시 그리지 않고(`notesListStale` 표시만) 칸에서 벗어날 때(`change`)·창을 닫을 때(`closeModal()`, `closeInlineDetail()`) `refreshNotesList()`로 다시 그림. 입력 중에 다시 그리면 메모를 다 지운 순간 그 부스가 메모 탭에서 빠져 펼친 상세가 닫히기 때문.
- 방문 상태: `VISIT_KEY`, `getVisitStatus/setVisitStatus`, `updateVisitVisuals()`
- 예산: `BUDGET_KEY`, `getBudget/setBudget/getTotalBudget`, `formatYen()`, `updateBudgetTotalDisplay()`
- 쓴 돈: `SPENT_KEY`(`furstclass-spent`), `loadSpent/saveSpent/getSpent/setSpent/getTotalSpent`. 상세 창 입력칸은 `fillBoothActions()`의 `.money-fields`(예산·쓴 돈 두 칸, `input[data-money]`). 합계 문구는 `updateBudgetTotalDisplay()`(`budgetTotal`/`spentTotal`/`spentTotalOver`/`spentTotalOnly`, 초과면 `.budget-total.over`). 카드 금액 줄 `.money-line`(`moneyLine*`).
  동기화(`pushToCloud`의 `spent`, `pullAndMergeFromCloud`), 데이터 초기화(`resetAllData`), 두 칸 부스 예전 번호 이전(`migrateMergedBoothIds(spent)`)에 포함.
- 메모 탭 필터: `notesVisitFilter` ("all" | "planned" | "visited" | "route"), 저장 키 `furstclass-notes-filter`
- 동선 보기: `renderGrid()`의 `isRouteView`(정렬: 구역 → 방문 완료 여부 → (우선순위) → 원래 순서, 구역 머리줄 `.route-group-head`, 문구 `routeCount`/`routeGroupLeft`/`routeGroupDone`/`emptyRoute`). 홀 이름은 `boothHallKey()`.
- 카드 바로 완료 버튼: `.quick-visit-btn`(문구 `quickVisitDone`/`quickVisitUndo`), 누르면 `setVisitStatus()` 후 `renderGrid()`. 같은 부스의 PC 펼침 상세는 방문 버튼 표시가 어긋나지 않게 닫음.

## 확인 방법
1. 부스 상세 창에서 메모 입력 → 카드 색이 주황으로 바뀌는지 확인
2. 방문 예정/완료 토글 → 노랑/초록으로 바뀌고 배치도에도 반영되는지 확인
3. 예산 입력 후 메모 탭 상단 합계가 맞는지 확인
4. 새로고침 후 값이 남아 있는지 확인
5. 메모를 쓰고 저장 버튼 없이 바로 창을 닫은 뒤 다시 열어 메모가 남아 있는지 확인. 메모 탭에서 메모를 다 지우는 동안 상세가 닫히지 않고, 닫은 뒤 그 부스가 목록에서 빠지는지 확인
6. 상세 창에서 쓴 돈을 적고 메모 탭 위 합계가 "예산 · 쓴 돈 · 남은 예산"으로 바뀌는지, 예산보다 많이 적으면 "초과"로 빨갛게 보이는지, 카드 아래 금액 줄이 맞는지 확인. 로그인했다면 "지금 동기화" 후 다른 기기에서 쓴 돈이 보이는지, 데이터 초기화 후 쓴 돈도 지워지는지 확인
7. 메모 탭에서 🧭 동선 보기를 눌러 구역 머리줄과 남은 곳 수가 맞는지, 카드의 "✓ 방문 완료"를 누르면 그 카드가 구역 맨 뒤로 가고 초록이 되는지, "↩ 되돌리기"로 돌아오는지, 새로고침해도 동선 보기가 유지되는지 확인
